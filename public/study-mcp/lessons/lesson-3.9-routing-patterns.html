Lesson 3.9 — Routing Patterns

Basic Routing · Conditional Looping · Multipath Routing — cách graph tự quyết định "đi đường nào tiếp theo" dựa vào state, và cách chặn vòng lặp vô hạn.

01 Khái niệm & ví dụ đời sống

Routing là cơ chế để graph tự quyết định đi tới node nào tiếp theo, dựa vào giá trị hiện tại của state. Bài học có 3 pattern:

PatternĐịnh nghĩa
Literal RoutingCondition function trả về 1 string cố định, map sang tên node qua path_map
Conditional LoopingRoute quay lại node trước đó nếu điều kiện chưa thoả, có counter chặn vòng lặp vô hạn
Multipath Routing1 condition function route sang nhiều hơn 2 nhánh khác nhau

Ví dụ đời sống: bạn là lễ tân tòa nhà văn phòng — khách nói phòng ban cần gặp → chỉ thẳng thang máy tương ứng (Literal). Bạn phân luồng nhiều phòng ban khác nhau cùng lúc (Multipath). Nếu khách chưa điền form, bạn bảo quay lại điền — nhưng tối đa 3 lần rồi cho qua luôn (Conditional Looping + max iterations).

03 Lệnh quan trọng + nâng cao

API cốt lõi:

core APIgraph.add_conditional_edges(
    source,        # tên node xuất phát
    path_function, # hàm nhận state → trả về string / list[string]
    path_map       # dict: {"logic_name": "ten_node_that"}
)

Literal Routing:

literal routingfrom typing import Literal

def route_after_classify(state) -> Literal["handle_billing", "handle_tech", "handle_general"]:
    category = state["category"]
    if category == "billing":
        return "handle_billing"
    elif category == "tech":
        return "handle_tech"
    return "handle_general"

graph.add_conditional_edges(
    "classify", route_after_classify,
    {"handle_billing": "billing_node", "handle_tech": "tech_node", "handle_general": "general_node"},
)

Conditional Looping (kèm max iterations guard):

conditional loopdef should_continue(state) -> Literal["revise", "finish"]:
    if state["quality_score"] >= 8:
        return "finish"
    if state["attempts"] >= 3:  # 👈 chặn vô hạn
        return "finish"
    return "revise"

graph.add_conditional_edges("evaluate", should_continue, {
    "revise": "generate",  # 👈 loop back về node trước
    "finish": END,
})

Lệnh nâng cao — recursion_limit (lớp bảo vệ thứ 2):

nâng caoapp = graph.compile()
app.invoke(input_data, config={"recursion_limit": 25})

Flags/options quan trọng:

  • path_map — rõ ràng hoá mapping, tránh lỗi khi đổi tên node
  • Literal[...] — type hint giúp IDE cảnh báo giá trị sai
  • attempts/iteration_count — counter chặn vòng lặp
  • recursion_limit — giới hạn cứng toàn graph

File cấu hình:

Không cần file config riêng — logic nằm hết trong code Python. Chỉ cần truyền config đúng lúc gọi .invoke():

config = {
    "configurable": {"thread_id": "abc"},
    "recursion_limit": 25,
}

🍡 Story Mode — Tanjiro và Đội Diệt Quỷ Routing
Tanjiro Kamado giải thích Routing Patterns bằng ẩn dụ hơi thở, Trụ Cột và nhiệm vụ diệt quỷ.

Chương 1 Literal Routing = Toàn Tập Trung Hơi Thở Nước

Tanjiro đứng trước Trụ Sở Diệt Quỷ, tay cầm thanh Nichirin, và một con quỷ tin báo vừa bay tới báo cáo: "category: quỷ_cấp_thấp". Tanjiro không cần suy nghĩ nhiều — cậu tra đúng "bản đồ nhiệm vụ" (giống hệt path_map): "quỷ_cấp_thấp" → cử Đội Trinh Sát A. Không lăn tăn, không rẽ nhánh thừa. Đây chính là Literal Routing: một giá trị string cụ thể, map thẳng sang một điểm đến cụ thể, y hệt cách hơi thở Nhất Chi (Thuỷ) luôn đi theo đúng 1 chiêu thức cố định khi gặp đúng tình huống.

🌊 Hơi Thở Nước — Nhất Chi: "Nếu state báo category == 'billing', ta route thẳng tới billing_node. Không phân vân, không tự sáng tác chiêu mới."

Chương 2 Multipath Routing = Toàn Trụ Cột Xuất Trận Cùng Lúc

Khi tin báo về việc Vô Diện Quỷ xuất hiện ở ba ngôi làng cùng lúc, Sản Nghiệp Xã Chủ (Oyakata-sama) không chỉ cử một Trụ Cột. Ông ra lệnh: Trụ Thuỷ tới làng A, Trụ Hoả tới làng B, Trụ Trùng tới làng C — 1 sự kiện, N nhánh xử lý khác nhau. Đó chính xác là Multipath Routing: hàm điều phối (route_task) không chỉ trả về một cái tên, mà trả về cả một danh sách nhánh để nhiều "Trụ Cột-node" cùng lên đường.

🔥 Hơi Thở Lửa — Rengoku: "Không phải lúc nào cũng if/else 2 nhánh đâu Tanjiro! Có lúc phải fan-out ra nhiều node một lúc — mỗi Trụ Cột lo một mặt trận!"

Chương 3 Conditional Looping = Luyện Thở Đến Khi Đạt Toàn Tập Trung

Tanjiro luyện "Hơi Thở Toàn Tập Trung Thường Trực" ngày này qua ngày khác. Sau mỗi lần luyện (generate), sư phụ Urokodaki chấm điểm (evaluate): nếu chưa đạt ngưỡng, Tanjiro quay lại luyện tiếp — loop back đúng node cũ. Nhưng Urokodaki không bắt cậu luyện vô hạn: có giới hạn số ngày tối đa trước kỳ thi Trụ Cột — giống hệt attempts >= max_iterations. Và nếu chẳng may cậu luyện "lụi" quá lâu không tiến bộ, có một quy tắc bảo vệ cứng hơn nữa: hạn chót tuyệt đối của kỳ thi — đó chính là recursion_limit, lớp bảo vệ thứ 2 phòng khi quy tắc "số ngày tối đa" bị quên mất.

🐗 Inosuke chen ngang: "Ta không cần đếm số lần! Ta mạnh là ta thắng luôn!" — Tanjiro: "Không được đâu Inosuke, không đếm attempts là core dump cả núi đó."

Chương cuối Tổng kết bằng một câu của Tanjiro

"Dù là chọn đúng một hướng đi (Literal), chia quân ra nhiều mặt trận (Multipath), hay lặp lại luyện tập đến khi đủ mạnh (Loop) — điều quan trọng nhất là luôn biết điểm dừng. Một chiến binh không có giới hạn sẽ kiệt sức giữa trận. Một graph không có max_iterations hay recursion_limit sẽ treo giữa production."
