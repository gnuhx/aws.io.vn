01 Khái niệm cốt lõi

Embedding biến 1 đoạn text thành 1 vector số (1536 chiều với text-embedding-3-small) mã hoá ý nghĩa chứ không phải mặt chữ.

📚 Ví dụ đời sống: Thay vì xếp sách theo bảng chữ cái tên tác giả, bạn xếp theo "toạ độ chủ đề". Sách về "chó" và "mèo" đứng gần nhau vì cùng nhóm "thú cưng"; sách "vũ trụ" đứng xa tít bên kia thư viện. Embedding = toạ độ đó, chỉ là không gian có 1536 chiều thay vì 3.

Vector Store là "thư viện" lưu vector + metadata + text gốc, cho phép hỏi "đưa tôi N cuốn gần toạ độ này nhất" — similarity search.

Metadata filtering giống như nói với thủ thư: "tìm sách gần chủ đề X, nhưng chỉ trong kệ xuất bản sau 2020" — lọc cứng trước khi so ý nghĩa.

Persistence = thư viện được ghi xuống đĩa, tắt máy mở lại vẫn còn, không phải re-embed từ đầu.

03 Lệnh quan trọng — Embeddings (2.13)

from langchain_openai import OpenAIEmbeddings

embeddings = OpenAIEmbeddings(model="text-embedding-3-small")

vec_docs  = embeddings.embed_documents(["văn bản 1", "văn bản 2"])  # batch → lưu trữ
vec_query = embeddings.embed_query("câu hỏi của user")              # 1 câu → tìm kiếm

model: text-embedding-3-small (1536-dim, rẻ) vs text-embedding-3-large (3072-dim, chính xác hơn, đắt hơn).

embed_documents() vs embed_query(): khác nhau ở batch vs single và cách normalize (asymmetric embedding).

from langchain.embeddings import CacheBackedEmbeddings
from langchain.storage import LocalFileStore

store = LocalFileStore("./cache/")
cached_embedder = CacheBackedEmbeddings.from_bytes_store(
    embeddings, store, namespace=embeddings.model
)

CacheBackedEmbeddings: tránh embed lại document đã embed rồi. namespace: tách cache theo model để không lẫn khi đổi model.

05 ChromaDB Hands-on (2.15)

from langchain_chroma import Chroma

vectorstore = Chroma.from_documents(
    documents=docs,
    embedding=embeddings,
    persist_directory="./chroma_db",   # ghi xuống đĩa
    collection_name="exam_samples"
)

persist_directory: flag quan trọng nhất — không có nó Chroma chỉ tồn tại trong RAM. collection_name: nhiều "bảng" logic trong cùng 1 thư mục.

results = vectorstore.similarity_search_with_score(
    query="hàm số bậc nhất", k=4
)  # score gần 0 = giống nhau (đây là DISTANCE)

results = vectorstore.similarity_search(
    query="hàm số bậc nhất", k=4,
    filter={"subject": "toan", "exam_type": "1tiet"}
)  # metadata filtering — lọc trước khi so vector

retriever = vectorstore.as_retriever(
    search_type="similarity",   # hoặc "mmr", "similarity_score_threshold"
    search_kwargs={"k": 4, "filter": {"subject": "toan"}}
)

k: số kết quả trả về — quá nhỏ thiếu context, quá lớn gây noise. as_retriever(): chuẩn hoá interface để cắm vào chain/agent (retriever.invoke(query)).

# Load lại từ đĩa — không re-embed
vectorstore = Chroma(
    persist_directory="./chroma_db",
    embedding_function=embeddings,
    collection_name="exam_samples"
)

⚠️ Phải dùng cùng embedding model giữa lúc tạo và lúc load — đổi model không lỗi ngay nhưng similarity search sẽ sai lệch vì số chiều không khớp ngữ nghĩa.

06 File cấu hình quan trọng

  • persist_directory — thư mục (không phải 1 file), Chroma tự quản lý SQLite + Parquet bên trong
  • .env — chứa OPENAI_API_KEY=sk-...
  • requirements.txt — langchain, langchain-openai, langchain-chroma, chromadb

07 Ứng dụng thực tế

  • Exam Generator (project của bạn): embed đề mẫu JSON, persist, retrieve theo metadata trước rồi semantic search topic
  • Documentation Helper: embed docs crawl được, filter theo URL/section trước khi trả context
  • Chatbot doanh nghiệp: filter theo department/product_line để tránh lẫn ngữ cảnh
  • Production scale: chuyển từ Chroma sang Pinecone/Qdrant/pgvector khi cần SLA + multi-tenant
