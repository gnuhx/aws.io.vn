Khái niệm

RAG (Retrieval-Augmented Generation) kết hợp Retrieval (tìm thông tin liên quan từ nguồn ngoài) và Generation (LLM sinh câu trả lời dựa trên thông tin đó). Thay vì bắt LLM "học thuộc" toàn bộ tài liệu, ta để nó tra cứu đúng đoạn cần thiết rồi mới trả lời — giảm hallucination, cập nhật kiến thức mới mà không cần train lại model.

4 trụ cột chất lượng RAG

Chunk qualityEmbedding qualityRetrieval strategyPrompt

  • Chunk quality — chunk quá nhỏ mất ngữ cảnh, quá lớn lẫn noise.
  • Embedding quality — model embedding có hiểu đúng domain dữ liệu không.
  • Retrieval strategy — similarity search, hybrid search, multi-query...
  • Prompt — cách đóng gói context trước khi đưa cho LLM.

Top-k — trade-off Context vs Noise

k nhỏ → gọn nhưng thiếu thông tin. k lớn → nhiều thông tin hơn nhưng tăng noise, tăng chi phí, dễ "lost in the middle". Best practice: bắt đầu k=3-5.

Re-ranking

Sau retrieval thô (nhanh, cosine similarity), sắp xếp lại bằng cross-encoder hoặc LLM chấm điểm — retrieval thô ưu tiên recall, re-ranking ưu tiên precision.

Evaluation

MetricĐo cái gì
Context Precision% chunk lấy được thực sự liên quan
Context Recall% chunk liên quan trong data được lấy ra
FaithfulnessCâu trả lời có bám sát context hay bịa
Answer RelevancyCâu trả lời có trả lời đúng câu hỏi

Công cụ phổ biến: RAGAS (ragas.evaluate(dataset, metrics=[...])).

Lệnh nâng cao — Re-ranking bằng Cross-Encoder

from sentence_transformers import CrossEncoder

reranker = CrossEncoder("cross-encoder/ms-marco-MiniLM-L-6-v2")

def rerank(query, docs, top_n=3):
    pairs = [(query, d) for d in docs]
    scores = reranker.predict(pairs)
    ranked = sorted(zip(docs, scores), key=lambda x: x[1], reverse=True)
    return [doc for doc, score in ranked[:top_n]]

🍡 Tanjiro Kamado và Kho Cuộn Nhật Ký

Tanjiro Kamado đi đánh quỷ, nhưng thay vì nhớ hết mọi trang nhật ký của các Trụ Cột trong đầu, cậu mang theo Kho Cuộn — những trang ghi lại điểm yếu từng con quỷ. Khi gặp quỷ mới, Tanjiro đặt câu hỏi, lấy về top_k trang có vẻ liên quan nhất, rồi dùng khứu giác để re-rank — lọc lại trang nào thật sự đúng — trước khi hành động. Sau trận, cậu đánh giá (evaluation) xem lời khuyên đó có đúng không.

Ánh xạ khái niệm

Code thật (đã chạy kiểm chứng)

# DEMO: RAG Architecture & Best Practices — Tanjiro Kamado Edition
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity
import numpy as np

# 1) "Cuon_Kinh" - cac trang nhat ky (documents) cua cac Hashira
cuon_kinh = [
    "Quy Nhen o nui Natagumo so nhat la lua va bi dut day to => dung Hinokami Kagura de chem dut day nhen chinh.",
    "Quy co dau o Yoshiwara co the tach roi dau khoi than, phai chem dut ca dau va co de no khong hoi sinh.",
    "Ha Bi Chuc Muzan so anh nang mat troi hon tat ca, chi ton thuong that su khi troi rang dong.",
    "Quy Ho o Natagumo dieu khien mang nhen tu tay, diem yeu la khop ngon tay tao ra nhen con.",
    "Enmu, quy cua giac mo, tan cong qua giac ngu, phai tu chem minh de thoat khoi giac mo va giet han khi con tinh.",
    "Akaza vo cung nhanh va khoe, chieu Sat Khi Sat Phong Toa cua Thuy Tru co the lam han cham lai.",
]
nhan_nhat_ky = ["Quy Nhen chua", "Quy dau Yoshiwara", "Muzan", "Quy Ho nhen con", "Enmu giac mo", "Akaza"]

# 2) "embed_cuon_kinh" - bien nhat ky thanh vector (TF-IDF = embedding that)
vectorizer = TfidfVectorizer()
kho_cuon_vector = vectorizer.fit_transform(cuon_kinh)   # = Kho_Cuon (vector store that)

def truy_van_tim_cuon(cau_hoi, top_k=3):
    """Tanjiro dat cau hoi -> tim top_k trang gan nhat (retrieval)."""
    vector_cau_hoi = vectorizer.transform([cau_hoi])
    diem_tuong_dong = cosine_similarity(vector_cau_hoi, kho_cuon_vector)[0]
    top_idx = np.argsort(diem_tuong_dong)[::-1][:top_k]
    return [(nhan_nhat_ky[i], cuon_kinh[i], round(float(diem_tuong_dong[i]), 4)) for i in top_idx]

def re_rank_bang_khuu_giac(cau_hoi, ket_qua_tho):
    """Dung 'khuu giac' (dem tu khoa trung khop that su) de sap xep lai top_k."""
    tu_khoa_cau_hoi = set(cau_hoi.lower().split())
    def diem_khuu_giac(item):
        _, noi_dung, diem_goc = item
        tu_khoa_noi_dung = set(noi_dung.lower().replace(",","").replace(".","").split())
        so_tu_trung = len(tu_khoa_cau_hoi & tu_khoa_noi_dung)
        return diem_goc + 0.05 * so_tu_trung
    return sorted(ket_qua_tho, key=diem_khuu_giac, reverse=True)

def danh_gia_ket_qua(cau_hoi, top1_nhan, dap_an_dung):
    dung = (top1_nhan == dap_an_dung)
    print(f"   -> Danh gia: {'DUNG' if dung else 'SAI'} (mong doi: {dap_an_dung})")
    return dung

# --- Tran danh 1: Quy Nhen chua ---
cau_hoi_1 = "quy nhen chua so gi de danh bai no"
tho_1 = truy_van_tim_cuon(cau_hoi_1, top_k=3)
sau_rerank_1 = re_rank_bang_khuu_giac(cau_hoi_1, tho_1)
danh_gia_ket_qua(cau_hoi_1, sau_rerank_1[0][0], "Quy Nhen chua")

# --- Tran danh 2: Akaza ---
cau_hoi_2 = "lam sao lam cham toc do cua quy nhanh nhu Akaza"
tho_2 = truy_van_tim_cuon(cau_hoi_2, top_k=3)
sau_rerank_2 = re_rank_bang_khuu_giac(cau_hoi_2, tho_2)
danh_gia_ket_qua(cau_hoi_2, sau_rerank_2[0][0], "Akaza")

Tại sao code này chạy được

Code chạy đúng không phải vì "phép màu Demon Slayer", mà vì bản chất kỹ thuật: TfidfVectorizer và cosine_similarity không quan tâm chuỗi text là "quỷ nhện chúa sợ lửa" hay bất kỳ nội dung nào khác — với máy, đó chỉ là chuỗi ký tự được vector hoá thành số theo tần suất từ, rồi đo góc giữa các vector. Đặt tên biến/hàm theo theme Demon Slayer chỉ là lớp "vỏ ngôn ngữ" giúp liên tưởng — thứ tự vận hành thật sự (embed → tính similarity → lấy top-k → re-rank theo tiêu chí phụ) mới là thứ quyết định kết quả đúng hay sai. Đây là bài học cốt lõi của RAG: retrieval chỉ đúng khi hiểu rõ nguyên lý vector hoá và ranking, không phải vì đặt tên biến "kêu" mà code tự thông minh hơn.
