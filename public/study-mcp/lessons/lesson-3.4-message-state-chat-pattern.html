1.1 Khái niệm

Ở Lesson 3.3 bạn đã học reducer: cơ chế quyết định state được ghi đè hay merge khi node trả dữ liệu mới. Message State là ứng dụng cụ thể của reducer đó cho bài toán hội thoại.

MessagesState là TypedDict dựng sẵn của LangGraph:

from langgraph.graph import MessagesState
# tương đương:
class MessagesState(TypedDict):
    messages: Annotated[list, add_messages]

So sánh operator.add vs add_messages

Hành vioperator.addadd_messages

Message trùng ID với cái cũAppend trùng (bug)Update đúng vị trí
Nhận string thôLỗi kiểuTự convert → HumanMessage

Vì messages cộng dồn qua mỗi turn, LLM ở turn N luôn thấy toàn bộ N-1 turn trước — đây là cách agent "nhớ" hội thoại mà không cần thêm hệ thống memory riêng.

1.2 Ví dụ đời sống

🏨 Hãy tưởng tượng cuốn sổ trực ban ở quầy lễ tân khách sạn. Khách hỏi → lễ tân ghi một dòng. Lễ tân đáp → ghi tiếp dòng dưới. Không bao giờ xé trang cũ, trang mới luôn thêm vào cuối để lật lại xem toàn bộ lịch sử.

Nếu lễ tân ghi nhầm, họ không xé trang — họ khoanh đúng mã dòng (ID) và viết đè lên đúng dòng đó. Đó chính là hành vi update-theo-ID của add_messages. Và "nội quy khách sạn" dán ở trang đầu sổ — chính là SystemMessage.

1.4 Lệnh quan trọng

from langgraph.graph import StateGraph, MessagesState, START, END
from langchain_core.messages import HumanMessage, AIMessage, SystemMessage

graph = StateGraph(MessagesState)

def call_model(state: MessagesState) -> dict:
    response = llm.invoke(state["messages"])
    return {"messages": [response]}  # add_messages tự append

graph.add_node("call_model", call_model)
graph.add_edge(START, "call_model")
graph.add_edge("call_model", END)

app = graph.compile()
result = app.invoke({"messages": [HumanMessage(content="Xin chào!")]})
Lệnh / FlagGiải thích
MessagesStateState type dựng sẵn, field messages có reducer add_messages.
add_messagesReducer: tự append, tự update theo ID, tự convert string → HumanMessage.
HumanMessageLượt nói của người dùng.
AIMessageLượt trả lời của model.
SystemMessageChỉ dẫn hệ thống, nên đặt đầu list.
ToolMessageKết quả 1 tool call, gắn với tool_call_id.
app.invoke(...)Chạy graph 1 lượt, trả state cuối.
app.stream(...)Chạy graph, trả từng bước real-time.

Lệnh nâng cao

from langgraph.graph.message import RemoveMessage

# Update 1 message theo ID (ghi đè, không append thêm dòng)
existing_id = result["messages"][-1].id
correction = AIMessage(content="Xin lỗi, chính xác là...", id=existing_id)
app.invoke({"messages": [correction]})

# Xóa 1 message khỏi lịch sử
app.invoke({"messages": [RemoveMessage(id=existing_id)]})

# Cắt bớt lịch sử dài trước khi gọi LLM
from langchain_core.messages.utils import trim_messages
trimmed = trim_messages(state["messages"], max_tokens=2000, strategy="last", token_counter=llm)

⚡ Cheat Sheet

Import cốt lõi

  • from langgraph.graph import MessagesState, StateGraph, START, END
  • from langgraph.graph.message import add_messages, RemoveMessage
  • from langchain_core.messages import HumanMessage, AIMessage, SystemMessage, ToolMessage

4 loại message

  • SystemMessage — chỉ dẫn nền, đặt đầu list
  • HumanMessage — lượt user
  • AIMessage — lượt model trả lời
  • ToolMessage — kết quả tool, gắn tool_call_id

Hành vi add_messages

  • ID mới → append
  • ID trùng → update (ghi đè đúng vị trí)
  • String thô → tự convert HumanMessage
  • RemoveMessage(id=...) → xóa khỏi lịch sử

File cấu hình

  • .env — API key
  • requirements.txt — langgraph, langchain-openai
  • langgraph.json — khi deploy Platform

Lab tóm tắt

  • Setup venv → cài langgraph, langchain-openai
  • Viết node call_model, build graph 1 node
  • Chạy 3 turns, tái sử dụng state trả về
  • Verify: số lượng message, model nhớ context, đúng thứ tự Human/AI

Bẫy dễ sai

  • Reset state rỗng mỗi turn → mất trí nhớ
  • Trả về state["messages"] + [msg] → duplicate
  • Quên Annotated[list, add_messages] khi tự định nghĩa state
  • ID sai khi update → ghi đè nhầm message

🎬 Bài học rút ra: Cuốn sổ của Tanjiro chính là MessagesState. Ghi thêm dòng mới = append. Sửa đúng dòng cũ bằng đánh số = update theo ID. Xé bỏ dòng nhiễu = RemoveMessage. Và tờ nội quy đầu sổ luôn ở đó = SystemMessage. Không có phép màu Hô Hấp nào ở đây cả — chỉ là một cuốn sổ được quản lý đúng cách!
