01 Khái niệm + Ví dụ đời sống

Multi-Node Pipeline là một StateGraph gồm nhiều node nối tiếp, trong đó output của node A trở thành input của node B, còn mọi state trung gian được lưu chung vào một State object xuyên suốt graph.

Ví dụ dây chuyền nhà máy

Mỗi trạm không cần biết trạm trước làm gì — chỉ cần đọc đúng field trong "phiếu theo dõi đơn hàng" (state) và ghi thêm dữ liệu của mình. Đây là decoupling: các node độc lập, dễ test riêng, dễ thêm/bớt trạm.

END

Ví dụ đời sống khác — khám bệnh viện

Tiếp nhận (ghi hồ sơ = state) → Đo sinh hiệu (thêm nhiệt độ, huyết áp) → Bác sĩ khám (thêm chẩn đoán) → Nhà thuốc (đọc chẩn đoán, in đơn thuốc). Hồ sơ chảy xuyên suốt 4 trạm — đúng bản chất "state chảy qua node".

03 Lệnh quan trọng + nâng cao

1. Khai báo State

from typing import TypedDict, List

class MyState(TypedDict):
    input_text: str
    classification: str
    result: str
    log: List[str]

2. Node function

def classify_node(state: MyState) -> dict:
    text = state["input_text"]
    label = "spam" if "buy now" in text else "normal"
    return {"classification": label}  # chỉ trả field cần update
Thành phầnGiải thích
state: MyStateNode luôn nhận toàn bộ state hiện tại
Return dictChỉ field cần update — LangGraph tự merge phần còn lại
Không mutate trực tiếpBest practice: tạo dict mới, không sửa state["x"] rồi return state

3. Build & compile graph

from langgraph.graph import StateGraph, START, END

graph = StateGraph(MyState)
graph.add_node("classify", classify_node)
graph.add_node("process", process_node)
graph.add_node("format", format_node)

graph.add_edge(START, "classify")
graph.add_edge("classify", "process")   # output A -> input B
graph.add_edge("process", "format")
graph.add_edge("format", END)

app = graph.compile()
LệnhFlag/OptionÝ nghĩa
StateGraph(MyState)class TypedDictKhởi tạo graph với schema state
add_node(name, fn)name, fnĐăng ký 1 trạm xử lý
add_edge(a, b)tên node/START/ENDNối cứng từ a → b
compile()—Biến graph thành object immutable, invoke được nhiều lần

4. Chạy graph

result = app.invoke({"input_text": "buy now!!!", ...})

Đường Ray Hơi Thở — Tanjiro và Pipeline Diệt Quỷ

Story Mode · Lesson 3.5 — Multi-Node Pipelines

Sau khi thấm nhuần State, Node, Edge (3.1-3.4), Tanjiro Kamado được giao nhiệm vụ đầu tiên như một "chuỗi hơi thở nối tiếp" — không phải 1 chiêu đơn lẻ, mà là 4 bước liên hoàn, mỗi bước đọc kết quả của bước trước để quyết định hành động tiếp theo. Đây chính là bản chất của Multi-Node Pipeline: output node A → input node B.

🗺️ Ánh xạ khái niệm ↔ chi tiết truyện

Khái niệm kỹ thuậtChi tiết trong truyện
State (TypedDict)"Sổ Tay Diệt Quỷ" — cuốn sổ chung mà mọi chiêu thở (node) đọc/ghi vào
Node functionTừng "chiêu thở" riêng biệt — nhận sổ tay hiện tại, trả về phần cập nhật

process_nodeTanjiro thi triển chiêu thức để hạ gục quỷ

🐗 Bug hài hước: field log trong state chính là "camera giám sát" ghi lại đúng thứ tự chiêu thở đã chạy. Nếu Inosuke (heo rừng) xông vào đánh trước khi Tanjiro kịp ngửi mùi, log sẽ lộ ngay vì thứ tự dòng ghi không khớp với graph đã định nghĩa — pipeline không "lười" phát hiện sai thứ tự, mà đơn giản là edges chỉ cho phép 1 con đường duy nhất từ START đến END.

💻 Code thật (LangGraph API thật, đã chạy)

from typing import TypedDict, List
from langgraph.graph import StateGraph, START, END


class SoTayDietQuy(TypedDict):
    quai_vat: str
    loai_quy: str
    ky_thuat: str
    ket_qua: str
    log: List[str]


def ngui_mui_node(state: SoTayDietQuy) -> dict:
    # Node 1 - CLASSIFY: ngui mui phan loai quy
    quai_vat = state["quai_vat"]
    if "nhen" in quai_vat.lower():
        loai = "quy_nhen_gia_toc"
    elif "vo han" in quai_vat.lower():
        loai = "quy_bat_tu"
    else:
        loai = "quy_thuong"
    return {
        "loai_quy": loai,
        "log": state["log"] + [f"[ngui_mui] phan loai '{quai_vat}' -> {loai}"],
    }


def chon_chieu_tho_node(state: SoTayDietQuy) -> dict:
    # Node 2 - ROUTE: output node truoc -> input node nay
    loai_quy = state["loai_quy"]
    if loai_quy == "quy_bat_tu":
        ky_thuat = "Tho Mat Troi - Chi Nhat Kagura"
    elif loai_quy == "quy_nhen_gia_toc":
        ky_thuat = "Tho Nuoc - De Nhat Hinh: Mien Nuoc Chay"
    else:
        ky_thuat = "Tho Nuoc - De Nhi Hinh: Boc Nuoc Xoay"
    return {
        "ky_thuat": ky_thuat,
        "log": state["log"] + [f"[chon_chieu_tho] {loai_quy} -> {ky_thuat}"],
    }


def thi_trien_node(state: SoTayDietQuy) -> dict:
    # Node 3 - PROCESS: thuc thi ky thuat
    ky_thuat = state["ky_thuat"]
    return {
        "ket_qua": f"Da ha guc bang [{ky_thuat}]",
        "log": state["log"] + [f"[thi_trien] executing '{ky_thuat}'"],
    }


def bao_cao_hashira_node(state: SoTayDietQuy) -> dict:
    # Node 4 - FORMAT: dong goi bao cao cuoi
    bao_cao = (
        f"BAO CAO NHIEM VU\n"
        f"- Doi tuong    : {state['quai_vat']}\n"
        f"- Phan loai    : {state['loai_quy']}\n"
        f"- Ky thuat dung: {state['ky_thuat']}\n"
        f"- Ket qua      : {state['ket_qua']}"
    )
    return {"ket_qua": bao_cao, "log": state["log"] + ["[bao_cao_hashira] da dong goi bao cao"]}


graph = StateGraph(SoTayDietQuy)
graph.add_node("ngui_mui", ngui_mui_node)
graph.add_node("chon_chieu_tho", chon_chieu_tho_node)
graph.add_node("thi_trien", thi_trien_node)
graph.add_node("bao_cao_hashira", bao_cao_hashira_node)

graph.add_edge(START, "ngui_mui")
graph.add_edge("ngui_mui", "chon_chieu_tho")
graph.add_edge("chon_chieu_tho", "thi_trien")
graph.add_edge("thi_trien", "bao_cao_hashira")
graph.add_edge("bao_cao_hashira", END)

app = graph.compile()

ket_qua = app.invoke({"quai_vat": "Quy Nhen (Nui Tu Nhien)", "loai_quy": "",
                       "ky_thuat": "", "ket_qua": "", "log": []})
print(ket_qua["ket_qua"])

🤔 Tại sao code này chạy được?

StateGraph của LangGraph không hề quan tâm field trong TypedDict tên là quai_vat hay input_text, hay logic trong node là "ngửi mùi quỷ" hay "phân loại email spam" — với framework, tất cả chỉ là 1 dict Python được truyền tuần tự qua các node theo đúng thứ tự add_edge đã khai báo, mỗi node trả về phần cập nhật, framework tự merge lại. Nói cách khác: tên biến/hàm là ẩn dụ cho người đọc, còn bản chất kỹ thuật chỉ là data (state) chảy qua graph theo thứ tự cạnh nối (edges) — không phải phép màu của "Hơi Thở". Vì vậy bạn có thể đổi toàn bộ theme Tanjiro sang theme "xử lý ticket khách hàng" mà code chạy y hệt, không đổi 1 dòng logic graph.
