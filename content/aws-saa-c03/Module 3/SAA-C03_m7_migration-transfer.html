7.2

AWS Migration Tools Overview

AWS không có "1 nút bấm" để migrate — mà cung cấp 1 bộ công cụ theo từng giai đoạn: Assess (đánh giá) → Mobilize (lên kế hoạch) → Migrate & Modernize (thực thi). AWS Migration Hub là bảng điều khiển trung tâm theo dõi tiến độ mọi công cụ ở 1 nơi. Ví dụ: công ty chuyển nhà trọn gói có 1 bảng điều phối trung tâm theo dõi cùng lúc đội khảo sát, đóng gói, xe tải, lắp đặt.

  • Assess: Application Discovery Service, Migration Evaluator
  • Mobilize: Migration Hub, Strategy Recommendations
  • Migrate & Modernize: DMS, MGN, DataSync, Snow Family, Transfer Family

Pattern nâng cao / case thực tế

Migration Hub Strategy Recommendations tự động chấm điểm và đề xuất 1 trong 7R cho từng server dựa trên dữ liệu Discovery.

Case: ngân hàng có ~800 server on-prem tích lũy 15 năm, không ai nhớ rõ dependency. Chạy Discovery Agent 2 tuần rồi dùng Strategy Recommendations phân loại tự động: server ít traffic → Retire; app .NET còn support → Rehost; core banking → Refactor. Rút thời gian lập kế hoạch từ nhiều tháng còn vài tuần.
🏭 Vị trí kiến trúc: Không phải trạm sản xuất — là "phòng kế hoạch mở rộng" đứng tách biệt ngoài dây chuyền, quan sát toàn bộ bản đồ nhà máy cũ và mới, không nằm trong luồng xử lý request khách hàng.

Lệnh quan trọng

aws migrationhub-config create-home-region-control \
  --home-region us-east-1 \
  --target '{"Type":"ACCOUNT","Id":"123456789012"}' \
  --dry-run false

aws migrationhub list-progress-update-streams

aws migrationhub list-created-artifacts \
  --progress-update-stream "OnPremStream" \
  --migration-task-name "AppServer-01"
Flag/LệnhViết tắtÝ nghĩa

7.3

AWS Application Discovery Service

Khảo sát hạ tầng on-premise trước khi di dời: thu thập cấu hình, mức sử dụng tài nguyên, và dependency giữa các server. Ví dụ: đội khảo sát đo đạc, chụp ảnh nhà cũ trước khi chuyển đồ, ghi chú món nào đi cùng món nào.

  • Agentless Connector: OVA trên VMware vCenter, không cần cài trên guest OS
  • Agent-based: cài trực tiếp trên server, chi tiết hơn (process, network connection) → dependency map chính xác

Pattern nâng cao / case thực tế

Dữ liệu dependency-map là đầu vào bắt buộc để Strategy Recommendations chấm điểm 7R chính xác.

Case: chuỗi bán lẻ có hệ thống POS legacy mất tài liệu kiến trúc. Cài Discovery Agent 3 tuần vẽ lại dependency thật, phát hiện 1 server "tưởng không ai dùng" thực chất đang phục vụ báo cáo tồn kho cuối ngày — tránh downtime nghiêm trọng.
🏭 Vị trí kiến trúc: Cùng nhóm "phòng kế hoạch mở rộng" — là đội khảo sát hiện trường, đầu vào cho Migration Hub Strategy Recommendations.

Lệnh quan trọng

aws discovery start-data-collection-by-agent-ids \
  --agent-ids i-0abc123 i-0def456

aws discovery describe-agents

aws discovery start-export-task \
  --export-data-format CSV

--export-data-formatExport FormatĐịnh dạng file xuất (CSV) chứa dữ liệu inventory

7.4

AWS Database Migration Service (DMS)

Di dời database với downtime tối thiểu — hỗ trợ homogeneous (Oracle→Oracle) và heterogeneous (Oracle→Aurora, cần AWS SCT convert schema trước). Ví dụ: xe tải chở đồ dễ vỡ, chạy liên tục nhiều chuyến trong khi kho cũ vẫn hoạt động, tới khi kho mới đầy đủ mới "khóa kho cũ" trong vài phút.

  • Full Load: copy toàn bộ dữ liệu hiện có 1 lần
  • CDC: tiếp tục bắt thay đổi (insert/update/delete) sau full load tới khi cutover
  • Replication instance: EC2 do DMS quản lý, chạy engine replication

Pattern nâng cao / case thực tế

Bật Multi-AZ cho replication instance khi CDC chạy dài hạn trong production để HA.

Case: sàn giao dịch chứng khoán migrate Oracle on-prem sang Aurora PostgreSQL, downtime tối đa 5 phút. Dùng SCT convert schema + DMS full-load-and-cdc chạy nhiều ngày, cutover đúng lúc thị trường đóng cửa cuối tuần.
🏭 Vị trí kiến trúc: Khớp vào Kho tổng — RDS/Aurora, đóng vai "đội bốc dỡ hàng chuyên trách tạm thời" đứng giữa kho cũ và kho tổng mới, tháo dỡ sau khi cutover xong.

Lệnh quan trọng

aws dms create-replication-instance \
  --replication-instance-identifier dms-repl-01 \
  --replication-instance-class dms.t3.micro \
  --allocated-storage 20 --multi-az false

aws dms create-endpoint \
  --endpoint-identifier source-oracle \
  --endpoint-type source --engine-name oracle \
  --server-name onprem-db.company.local --port 1521

aws dms create-replication-task \
  --replication-task-identifier task-01 \
  --migration-type full-load-and-cdc \
  --table-mappings file://table-mappings.json
FlagViết tắtÝ nghĩa
--replication-instance-classInstance ClassSize EC2 chạy engine DMS
--allocated-storageStorageỔ đĩa (GB) lưu log/cache
--multi-azMulti-AZStandby instance AZ khác cho HA
--endpoint-typeEndpoint Typesource/target
--migration-typeMigration Typefull-load / cdc / full-load-and-cdc

7.5

AWS Application Migration Service (MGN)

Lift-and-shift toàn bộ server sang AWS bằng replicate liên tục ở mức block-level, không cần convert OS. MGN là bản kế thừa mặc định của CloudEndure Migration. Ví dụ: chở nguyên khối căn nhà sang vị trí mới, dựng lại y hệt kiến trúc cũ trên nền đất mới (EC2).

  • Continuous replication vào staging area (EC2 nhẹ)
  • Test instance: launch thử để verify trước khi cutover thật
  • Cutover: launch instance production thật

Pattern nâng cao / case thực tế

Luôn chạy start-test trước để verify network/license/driver trước khi start-cutover thật.

Case: startup SaaS rời datacenter thuê ngoài trong 30 ngày, hơn 100 VM VMware. Replicate liên tục 2 tuần, test theo nhóm service, cutover hàng loạt cuối tuần khi traffic thấp — giữ gần 100% uptime.
🏭 Vị trí kiến trúc: Khớp vào Xưởng lắp ráp — EC2 — MGN là "đội dựng nhà y hệt bản gốc" đưa server cũ vào đúng vị trí xưởng lắp ráp trong subnet private.

Lệnh quan trọng

aws mgn describe-source-servers

aws mgn start-test \
  --source-server-id s-1234567890abcdef0

aws mgn start-cutover \
  --source-server-id s-1234567890abcdef0

aws mgn finalize-cutover \
  --source-server-id s-1234567890abcdef0
LệnhViết tắtÝ nghĩa
--source-server-idSource ServerID server đang được replicate
start-testTest LaunchLaunch instance thử, không ảnh hưởng production
start-cutoverCutoverLaunch instance production thật
finalize-cutoverFinalizeHoàn tất, dừng replication

So sánh nhanh

Tiêu chíMGNDMS
Đối tượngToàn bộ serverChỉ database
Cơ chếBlock-level liên tụcFull load + CDC bản ghi

7.6

AWS DataSync

Chuyển file/dữ liệu giữa on-premise storage (NFS/SMB) và AWS storage (S3, EFS, FSx), chạy 1 lần hoặc định kỳ theo lịch. Ví dụ: băng chuyền tự động chở hàng theo lịch cố định giữa 2 kho, tự nhận diện món mới/đổi để chỉ chở phần thay đổi.

  • DataSync Agent: VM on-premise kết nối NFS/SMB
  • Task: định nghĩa location, filter, schedule

Pattern nâng cao / case thực tế

Kết hợp schedule với EventBridge để trigger xử lý thêm sau khi transfer xong.

Case: hãng hậu kỳ phim đồng bộ hàng chục TB file dựng phim mỗi đêm từ NAS on-prem lên S3 cho render farm. DataSync task chạy cron mỗi đêm, chỉ đồng bộ phần thay đổi trong ngày.
🏭 Vị trí kiến trúc: Khớp vào Kho hàng tĩnh — S3 (hoặc EFS/FSx) — "băng chuyền nối kho cũ-mới", chạy định kỳ khác MGN/DMS chỉ chạy 1 lần.

Lệnh quan trọng

aws datasync create-location-nfs \
  --server-hostname 10.0.1.50 \
  --subdirectory /export/data \
  --on-prem-config AgentArns=arn:...:agent/agent-01

aws datasync create-location-s3 \
  --s3-bucket-arn arn:aws:s3:::my-migration-bucket \
  --s3-config BucketAccessRoleArn=arn:...:role/DataSyncRole

aws datasync create-task \
  --source-location-arn arn:...:location/loc-nfs \
  --destination-location-arn arn:...:location/loc-s3 \
  --schedule ScheduleExpression="cron(0 2 * * ? *)"

aws datasync start-task-execution --task-arn arn:...:task/task-01
FlagViết tắtÝ nghĩa
--server-hostnameNFS HostnameServer NFS on-prem cần đồng bộ
--on-prem-configOn-Prem ConfigTrỏ tới DataSync Agent
--s3-configS3 ConfigIAM role ghi vào bucket đích
--scheduleScheduleBiểu thức cron tần suất chạy

7.7

AWS Snow Family

Thiết bị vật lý chuyển dữ liệu khối lượng lớn khi mạng quá chậm — "không đường truyền nào nhanh bằng 1 xe tải chở đầy ổ cứng". Ví dụ: bể nước quá lớn để bơm qua ống nhỏ trong thời gian hợp lý, người ta chở nguyên bể bằng xe tải.

  • Snowcone (~8TB): edge computing, data nhỏ
  • Snowball Edge (~80TB): vừa storage vừa compute tại chỗ (EC2/Lambda)
  • Snowmobile (tới 100PB): container 45-foot, di dời datacenter cực lớn

Pattern nâng cao / case thực tế

Dùng OpsHub để chạy EC2/Lambda ngay trên Snowball Edge tại hiện trường, xử lý sơ bộ trước khi gửi về AWS.

Case: công ty dầu khí thu thập dữ liệu địa chất tại giàn khoan không có Internet. Dùng Snowball Edge Compute Optimized chạy inference AI ngay tại chỗ, chỉ gửi kết quả đã xử lý về AWS.
🏭 Vị trí kiến trúc: "Cửa nhận hàng hóa vật lý" — cổng riêng ngoài network layer (Route 53/CloudFront/VPC), đưa thẳng dữ liệu vật lý vào Kho tổng/Kho tĩnh.

Lệnh quan trọng

aws snowball create-job \

  --shipping-option SECOND_DAY

aws snowball list-jobs

--shipping-optionShippingTốc độ vận chuyển thiết bị

The 7 Rs of Migration

7 chiến lược di dời ứng dụng. Ví dụ chuyển nhà: có món bỏ luôn (Retire), để lại (Retain), chuyển y nguyên (Rehost), đóng nguyên khối (Relocate), mua đồ mới (Repurchase), đổi kiểu dáng (Replatform), đóng lại hoàn toàn (Refactor).

Chiến lượcÝ nghĩa
RetireNgừng dùng, không migrate
RetainGiữ nguyên tại chỗ
RehostLift-and-shift (AWS MGN)
RelocateDi dời nguyên khối ảo hóa (VMware Cloud on AWS)
RepurchaseChuyển sang SaaS mới
ReplatformĐổi 1 phần nền tảng, giữ kiến trúc chính
RefactorThiết kế lại cloud-native

Pattern nâng cao / case thực tế

Strategy Recommendations chấm điểm 7R tự động, nhưng quyết định cuối vẫn cần cân nhắc thêm ROI/rủi ro nghiệp vụ.

Case: tập đoàn bán lẻ 500 app legacy. Strategy Recommendations phân loại: ~150 app → Retire, ~250 app → Rehost bằng MGN, ~100 app giá trị lâu dài → lộ trình Refactor sang serverless trong 2 năm.
🏭 Vị trí kiến trúc: Không phải trạm — là bộ tiêu chí quyết định cách xây MỖI trạm trong nhà máy, áp dụng cho mọi trạm từ Module 2 tới giờ.

So sánh nhanh — Effort & Tool

RetireRất thấp—
RetainKhông làm gì—

RepurchaseTrung bình— (SaaS bên thứ 3)
ReplatformTrung bìnhAWS DMS, RDS

Pattern chuẩn cần nhớ nằm lòng

Discovery → Strategy Recommendations (chọn 7R) → DMS (data) / MGN (server) / DataSync (file, định kỳ) / Snow Family (khi mạng quá chậm) → Migration Hub (theo dõi tổng tiến độ). Heterogeneous DB luôn cần SCT trước DMS. Lift-and-shift hàng loạt VM: MGN agent → replicate → test → cutover theo lô, ưu tiên giờ traffic thấp.

🏭 Trạm mới thêm vào nhà máy nền ở section này
  • Phòng kế hoạch mở rộng — Migration Hub + Discovery + Strategy Recommendations
  • Đội bốc dỡ hàng chuyên trách — AWS DMS, giữa kho cũ và Kho tổng RDS/Aurora
  • Đội dựng nhà y hệt bản gốc — AWS MGN, vào Xưởng lắp ráp EC2
  • Băng chuyền chạy định kỳ — AWS DataSync, cùng khu Kho hàng tĩnh S3/EFS/FSx
  • Cửa nhận hàng hóa vật lý — AWS Snow Family, ngoài network layer
  • 7 Rs — bộ tiêu chí quyết định cách xây mỗi trạm hiện có
