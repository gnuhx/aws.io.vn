6.33 — AWS Directory Service

Khái niệm: AD managed trên AWS. Như sổ hộ khẩu trung tâm biết ai thuộc phòng ban nào.

  • Managed Microsoft AD: đầy đủ, dữ liệu trên AWS
  • AD Connector: proxy tới AD on-premise, không lưu data
  • Simple AD: cơ bản, rẻ

Case: ngân hàng dùng AD Connector nối AD on-premise, không duplicate dữ liệu user lên cloud.

Vị trí kiến trúc: Lớp phủ an ninh cạnh IAM — sổ hộ khẩu kiểu AD.

5 câu hỏi
  1. AD Connector khác Managed AD? → Chỉ proxy, không lưu data trên AWS.
  2. Ngân hàng dùng lại AD cũ không duplicate? → AD Connector.
  3. Loại rẻ nhất? → Simple AD.
  4. AD Connector cần gì trước? → VPN/Direct Connect thông tới on-premise.
  5. Khớp đâu? → Cạnh IAM, sổ hộ khẩu AD.
aws ds create-microsoft-ad --name corp.example.com \
  --password 'P@ssw0rd123' \
  --vpc-settings VpcId=vpc-abc,SubnetIds=subnet-1,subnet-2

aws ds connect-directory --name corp.example.com \
  --connect-settings VpcId=vpc-abc,SubnetIds=subnet-1,subnet-2,\
CustomerDnsIps=10.0.0.5,CustomerUserName=admin
So sánhManaged ADAD ConnectorSimple AD
DataTrên AWSOn-premiseTrên AWS

6.34 — Identity Providers and Federation

Khái niệm: Đăng nhập bằng danh tính có sẵn (IdP) lấy quyền tạm thời vào AWS. Như dùng thẻ công ty mẹ vào thăm chi nhánh.

  • SAML: enterprise (AD/Okta) → STS
  • Web Identity/OIDC: consumer (Google/FB) → Cognito

Case: tập đoàn 5000 nhân viên SSO qua IAM Identity Center, tắt quyền tức thời khi nghỉ việc bằng cách vô hiệu ở AD.

Vị trí kiến trúc: Lớp phủ IAM — cổng công nhận thẻ đối tác.

5 câu hỏi
  1. Federation giải quyết vấn đề gì? → Không cần IAM User riêng cho từng người.
  2. SAML dùng cho ai, Web Identity cho ai? → Nội bộ AD/Okta vs người dùng cuối app.
  3. Tắt quyền nhanh nhất khi nghỉ việc? → Vô hiệu ở IdP gốc.
  4. Lệnh STS đổi SAML assertion? → assume-role-with-saml.
  5. Khớp đâu? → Lớp phủ IAM, cổng công nhận thẻ đối tác.
aws iam create-saml-provider --name CorpADFederation \
  --saml-metadata-document file://adfs-metadata.xml

aws sts assume-role-with-saml \
  --role-arn arn:aws:iam::123456789012:role/FederatedRole \
  --principal-arn arn:...:saml-provider/CorpADFederation \
  --saml-assertion file://assertion.xml
So sánhSAMLWeb Identity
Dùng choNhân viên nội bộNgười dùng cuối app

6.36 — Amazon Cognito

Khái niệm: User Pool (danh tính, JWT) + Identity Pool (đổi token lấy temp AWS credentials). Như lễ tân cấp thẻ khách + đổi thẻ lấy chìa tạm.

Case: app chia sẻ ảnh, mobile upload thẳng S3 qua Identity Pool, không qua server trung gian.

Vị trí kiến trúc: Trạm mới — quầy lễ tân khách vãng lai, khác IAM/Federation (nhân viên).

5 câu hỏi
  1. User Pool vs Identity Pool? → Danh tính (JWT) vs temp AWS credentials.
  2. Upload thẳng S3 không qua server? → Identity Pool.
  3. Mỗi user chỉ upload thư mục riêng? → Policy dùng ${cognito-identity...:sub}.
  4. Guest access gọi là gì? → Unauthenticated identities.
  5. Khớp đâu? → Trạm mới, quầy lễ tân khách vãng lai.
aws cognito-idp create-user-pool --pool-name my-app-users \
  --mfa-configuration OPTIONAL
aws cognito-identity create-identity-pool \
  --identity-pool-name my_app_identity \
  --allow-unauthenticated-identities
So sánhUser PoolIdentity Pool
Trả vềJWTTemp AWS credentials

6.37 — Encryption Primer

Khái niệm: At rest (lưu trữ) vs in transit (truyền). Symmetric (1 khóa) vs Asymmetric (cặp public/private). Như 1 chìa dùng chung vs hộp thư công khai + chìa riêng mở.

Pattern: TLS dùng asymmetric để handshake trao đổi khóa an toàn, rồi chuyển symmetric cho tốc độ truyền dữ liệu lớn.

Vị trí kiến trúc: Không phải trạm — nguyên lý vận hành của KMS.

5 câu hỏi
  1. At rest vs in transit? → Lưu trữ vs truyền đi.
  2. Vì sao TLS cần asymmetric ban đầu? → An toàn trao đổi khóa qua kênh chưa an toàn.
  3. Ký số dùng khóa nào? → Asymmetric.
  4. AES-256 loại gì? → Symmetric.
  5. Khớp đâu? → Nguyên lý nền của KMS.
So sánhSymmetricAsymmetric
Tốc độNhanhChậm
Số khóa1Cặp public/private
Ví dụAES-256RSA, ECC

6.38 — AWS Key Management Service (KMS)

Khái niệm: Tủ khóa trung tâm. Envelope Encryption: Data Key mã hóa dữ liệu (nhanh), Data Key được CMK mã hóa lại.

Pattern: Key Policy + kms:ViaService giới hạn key chỉ cho 1 service dùng. Case: ngân hàng dùng CMK riêng để có thể disable tức thời khi rò rỉ.

Vị trí kiến trúc: Đúng là tủ khóa trung tâm đã có sẵn.

5 câu hỏi
  1. Vì sao cần Envelope Encryption? → Encrypt trực tiếp giới hạn 4KB.
  2. AWS Managed vs CMK? → CMK tùy chỉnh policy, disable được.
  3. Ngân hàng cần thu hồi tức thời chọn gì? → CMK.
  4. Giới hạn key cho 1 service? → kms:ViaService.
  5. Khớp đâu? → Tủ khóa trung tâm có sẵn.
aws kms create-key --description "prod-app-key" \
  --key-usage ENCRYPT_DECRYPT
aws kms generate-data-key --key-id alias/prod-app-key \
  --key-spec AES_256
aws kms enable-key-rotation --key-id alias/prod-app-key
So sánhAWS ManagedCMK
RotationTự động, không tắtTùy chọn
Chi phíMiễn phíTrả phí

6.40 — AWS CloudHSM

Khái niệm: HSM single-tenant, AWS không truy cập được khóa. Như mua két sắt riêng thay vì thuê ngăn tủ chung.

Case: công ty thanh toán quốc tế cần PCI-DSS mức cao nhất, AWS không được truy cập khóa dưới bất kỳ hình thức nào.

Vị trí kiến trúc: Nhánh đặc biệt cạnh KMS — két sắt riêng biệt.

5 câu hỏi
  1. Khác biệt cốt lõi với KMS? → Single-tenant, AWS không truy cập được.
  2. Chuẩn compliance đạt được? → FIPS 140-2 Level 3.
  3. Rủi ro lớn nhất? → Mất credential, AWS không khôi phục được.
  4. PCI-DSS cao nhất chọn gì? → CloudHSM.
  5. Khớp đâu? → Nhánh đặc biệt cạnh KMS.
aws cloudhsmv2 create-cluster --hsm-type hsm1.medium \
  --subnet-ids subnet-1 subnet-2
aws cloudhsmv2 create-hsm --cluster-id cluster-abc \
  --availability-zone ap-southeast-1a
So sánhKMSCloudHSM
TenancyMultiSingle
ComplianceFIPS 140-2 L2FIPS 140-2 L3

6.41 — AWS Certificate Manager

Khái niệm: Cấp SSL/TLS miễn phí, tự gia hạn khi gắn dịch vụ AWS. Như con dấu xác nhận danh tính tự đóng dấu mới trước khi hết hạn.

Pattern: Luôn chọn DNS validation cho true auto-renewal. Case: website dùng CloudFront+ACM+Route53, không ai cần nhớ gia hạn.

Vị trí kiến trúc: Trạm mới ở ALB/CloudFront — con dấu danh tính.

5 câu hỏi
  1. Vì sao chọn DNS thay vì Email validation? → Auto-renew hoàn toàn.
  2. Xuất private key dùng ở nơi khác được không? → Không.
  3. SAN dùng để làm gì? → Thêm domain phụ vào 1 cert.
  4. Chi phí khi dùng ALB/CloudFront? → Miễn phí.
  5. Khớp đâu? → Trạm mới ở ALB/CloudFront.
aws acm request-certificate --domain-name example.com \
  --subject-alternative-names www.example.com \
  --validation-method DNS
So sánhDNS ValidationEmail Validation
Auto-renewHoàn toànCần xác nhận tay

6.43 — AWS Web Application Firewall (WAF)

Khái niệm: Lọc HTTP Layer 7 (SQLi, XSS, rate limit, geo-block). Như trạm soát người kiểm tra hành lý ngay cổng.

Case: website tin tức bị bot cào nội dung — WAF rate-based rule giới hạn 100 req/5 phút/IP.

Vị trí kiến trúc: Đúng vị trí trạm soát người tại cổng/ALB đã có sẵn.

5 câu hỏi
  1. WAF khác Security Group ở tầng nào? → Layer 7 vs Layer 4.
  2. Chặn bot cào nội dung? → Rate-based Rule.
  3. Scope CLOUDFRONT vs REGIONAL? → Global CDN vs 1 region (ALB/API GW).
  4. Rule sẵn chặn SQLi/XSS? → Managed Rule Groups.
  5. Khớp đâu? → Đúng vị trí có sẵn — cổng bảo vệ/ALB.
aws wafv2 create-web-acl --name my-web-acl --scope CLOUDFRONT \
  --default-action Allow={} --rules file://rules.json \
  --visibility-config SampledRequestsEnabled=true,\
CloudWatchMetricsEnabled=true,MetricName=myacl
So sánhWAFSG/NACL
TầngLayer 7Layer 3/4

6.44 — Amazon Inspector

Khái niệm: Quét lỗ hổng (CVE) trên EC2/ECR/Lambda. Như đội kiểm tra an toàn lao động tìm vết nứt thiết bị trước khi gây tai nạn.

Case: DevSecOps chặn CI/CD pipeline nếu Docker image có CVE CRITICAL trước khi push ECR.

Vị trí kiến trúc: Lớp phủ an ninh — đội kiểm tra thiết bị định kỳ.

5 câu hỏi
  1. Khác GuardDuty? → Quét lỗ hổng chủ động vs phát hiện tấn công đang xảy ra.
  2. Network Reachability giúp gì? → Ưu tiên vá theo rủi ro thực tế (khai thác được từ internet).
  3. Case CI/CD dùng để làm gì? → Fail build nếu CVE CRITICAL.
  4. Scan được resource nào? → EC2, ECR, Lambda.
  5. Khớp đâu? → Đội kiểm tra thiết bị định kỳ.
aws inspector2 enable --resource-types EC2 ECR LAMBDA
aws inspector2 list-findings --filter-criteria \
  '{"severity":[{"comparison":"EQUALS","value":"CRITICAL"}]}'
So sánhInspectorGuardDutyConfig
Phát hiệnCVEHành vi tấn côngCấu hình lệch

6.45 — Amazon Macie

Khái niệm: ML quét S3 tìm dữ liệu nhạy cảm (PII). Như mắt thần đi qua kho hàng tìm thùng chứa hàng đặc biệt.

Case: công ty y tế phát hiện bucket cũ bị bỏ quên chứa hồ sơ bệnh nhân ở chế độ public.

Vị trí kiến trúc: Lớp phủ an ninh chuyên trách S3 — mắt thần.

5 câu hỏi
  1. Macie quét gì, ở đâu? → PII trong S3.
  2. Nhận diện định dạng riêng công ty? → Custom Data Identifier.
  3. Case y tế phát hiện gì? → Bucket cũ public chứa hồ sơ bệnh nhân.
  4. Khác Inspector? → Nội dung dữ liệu vs lỗ hổng phần mềm.
  5. Khớp đâu? → Mắt thần chuyên trách S3.
aws macie2 enable-macie
aws macie2 create-classification-job --job-type ONE_TIME \
  --s3-job-definition '{"bucketDefinitions":[{"accountId":"123456789012","buckets":["my-data-bucket"]}]}' \
  --name scan-customer-data

6.46 — AWS GuardDuty

Khái niệm: Threat detection liên tục từ VPC Flow Logs/CloudTrail/DNS logs, ML + threat intel. Đúng vai đội an ninh tuần tra — không cần cấu hình rule.

Case: phát hiện credential bị đánh cắp, kết hợp EventBridge+Lambda tự thu hồi trong vài giây.

Vị trí kiến trúc: Đúng vị trí đội tuần tra có sẵn, dùng lại data CloudTrail/VPC Flow Logs.

5 câu hỏi
  1. Nguồn dữ liệu? → VPC Flow Logs, CloudTrail, DNS logs.
  2. Cần tự viết rule không? → Không, tự học hành vi.
  3. Case credential bị đánh cắp xử lý sao? → GuardDuty+EventBridge+Lambda tự thu hồi.
  4. Severity score khoảng nào? → 0.1–8.9.
  5. Khớp đâu? → Đội tuần tra có sẵn.
aws guardduty create-detector --enable
aws guardduty list-findings --detector-id abc123 \
  --finding-criteria '{"Criterion":{"severity":{"Gte":7}}}'

6.47 — AWS Shield

Khái niệm: Bảo vệ DDoS. Như hàng rào chắn đám đông ở cổng nhà máy.

  • Standard: miễn phí, tự bật, Layer 3/4
  • Advanced: ~$3000/tháng, Layer 3/4/7, DRT 24/7, cost protection

Case: sàn giao dịch mua Advanced vì cost protection — hoàn phí scale-out do DDoS gây ra.

Vị trí kiến trúc: Lớp phủ an ninh cùng nhóm WAF — chặn tầng mạng trước WAF.

5 câu hỏi
  1. Standard cần đăng ký không? → Không, tự động miễn phí.
  2. Advanced có gì Standard không có? → Layer 7, DRT, cost protection.
  3. Vì sao mua Advanced ngoài bảo vệ? → Cost protection.
  4. Shield chặn loại tấn công gì? → DDoS.
  5. Khớp đâu? → Cùng nhóm WAF, chặn Layer 3/4 trước.
aws shield subscribe
aws shield create-protection --name my-alb-protection \
  --resource-arn arn:aws:elasticloadbalancing:...:loadbalancer/app/my-alb
So sánhStandardAdvanced
Chi phíFree~$3000/tháng

6.48 — Defense In-Depth

Khái niệm: Xếp chồng nhiều lớp bảo mật độc lập, không dựa 1 lớp duy nhất. Đây là toàn bộ triết lý nhà máy nền: tường rào, bảo vệ cửa, thẻ ra vào, camera, tủ khóa.

Case: ngân hàng số 5 lớp độc lập — pen test tìm lỗi ở Security Group nhưng IAM+KMS vẫn chặn tiếp, dữ liệu vẫn an toàn.

Vị trí kiến trúc: Không phải trạm — triết lý toàn bộ lớp phủ an ninh.

5 câu hỏi
  1. Defense in Depth là gì? → Nhiều lớp bảo mật độc lập xếp chồng.
  2. 1 lớp lỗi thì sập hết không? → Không nếu thiết kế đúng.
  3. 5 lớp ngân hàng số gồm gì? → Network perimeter, segmentation, Identity, Data, Detection.
  4. Có phải 1 dịch vụ cụ thể? → Không, là nguyên tắc kiến trúc.
  5. Khớp đâu? → Triết lý toàn bộ lớp phủ an ninh.
LớpDịch vụ
Network perimeterShield, WAF, NACL
Network segmentationVPC, Security Group
IdentityIAM, Federation, MFA
Data protectionKMS, CloudHSM, ACM
Detection & ResponseGuardDuty, Inspector, Macie, Config, CloudTrail

Quiz — Security

1. SAML Federation dùng cho đối tượng nào?
Nhân viên nội bộ dùng danh tính có sẵn ở AD/Okta.
2. Muốn mobile app upload thẳng lên S3 mà không cần server trung gian, dùng gì?
Amazon Cognito Identity Pool (cấp temp AWS credentials).
3. Khác biệt cốt lõi giữa KMS và CloudHSM?
KMS multi-tenant (AWS hỗ trợ được); CloudHSM single-tenant (AWS không truy cập được khóa).
4. Vì sao nên dùng DNS validation cho ACM thay vì Email?
Cho phép auto-renew hoàn toàn, không phụ thuộc email admin domain.
5. WAF hoạt động ở tầng OSI nào, khác Security Group ra sao?
Layer 7 (hiểu nội dung HTTP); Security Group chỉ Layer 4 (port/protocol).
6. Phân biệt Inspector, Macie, GuardDuty?
Inspector = lỗ hổng phần mềm; Macie = PII trong S3; GuardDuty = hành vi tấn công thời gian thực.
7. Vì sao công ty mua Shield Advanced ngoài khả năng chặn DDoS mạnh hơn?
Cost protection — hoàn phí scale-out phát sinh do tấn công DDoS.
8. Defense in Depth có phải là 1 dịch vụ AWS cụ thể không?
Không — là nguyên tắc kiến trúc xếp chồng nhiều lớp bảo mật độc lập.

Lab tổng — Dựng hệ thống bảo mật nhiều lớp

  • kms schedule-key-deletion chờ tối thiểu 7 ngày — thiết kế an toàn cố ý.
  • WAF Web ACL phải disassociate TRƯỚC khi delete.
  • GuardDuty/Macie tính phí theo lượng log/data — disable ngay sau khi test.
  • Shield Advanced (~$3000/tháng) KHÔNG nên bật thử trong lab cá nhân.

Cheat Sheet — Security

Federation vs Cognito

SAML = nhân viên nội bộ (AD/Okta). Cognito = người dùng cuối app (mobile/web).

KMS vs CloudHSM

KMS = tủ khóa chung (multi-tenant, AWS hỗ trợ). CloudHSM = két riêng (single-tenant, AWS không truy cập).

ACM

SSL miễn phí, DNS validation cho auto-renew hoàn toàn, chỉ gắn được dịch vụ AWS.

WAF vs SG/NACL vs Shield

WAF = Layer 7. SG/NACL = Layer 3/4. Shield = DDoS tầng mạng trước WAF.

Inspector vs Macie vs GuardDuty

Inspector = CVE phần mềm. Macie = PII trong S3. GuardDuty = hành vi tấn công thời gian thực.

Defense in Depth

Xếp chồng nhiều lớp độc lập — luôn đúng khi đề hỏi "thiết kế bảo mật toàn diện nhất".

🎯 Pattern chuẩn thi

SSO hàng nghìn nhân viên, tắt quyền tức thời → SAML Federation qua IAM Identity Center. Compliance yêu cầu AWS không truy cập khóa → CloudHSM. Chặn bot/brute-force → WAF Rate-based Rule. Phát hiện PII bị bỏ quên → Macie. Phản ứng tự động credential bị đánh cắp → GuardDuty + EventBridge + Lambda.

🏭 Trạm mới thêm vào nhà máy nền

  • Directory Service — sổ hộ khẩu AD, cạnh IAM
  • Federation — cổng công nhận thẻ đối tác
  • Cognito — quầy lễ tân khách vãng lai (trạm mới)
  • KMS — xác nhận tủ khóa trung tâm có sẵn + Envelope Encryption
  • CloudHSM — két sắt riêng biệt, nhánh đặc biệt cạnh KMS
  • ACM — con dấu danh tính ở ALB/CloudFront (trạm mới)
  • WAF — xác nhận trạm soát người có sẵn
  • Inspector/Macie/GuardDuty — 3 lớp camera an ninh chuyên biệt
  • Shield — hàng rào chắn đám đông, cùng nhóm WAF
  • Defense in Depth — triết lý toàn bộ lớp phủ an ninh
