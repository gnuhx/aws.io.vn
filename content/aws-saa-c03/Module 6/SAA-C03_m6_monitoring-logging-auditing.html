6.19 — Amazon CloudWatch Overview

Khái niệm: Thu thập metric, tạo Alarm khi vượt ngưỡng, Dashboard hiển thị. Như đồng hồ đo áp suất/nhiệt độ gắn khắp nhà máy, kim vượt vạch đỏ thì còi kêu.

  • Basic: 5 phút, miễn phí
  • Detailed: 1 phút, trả phí thêm
  • Custom Metric: tự đẩy số liệu app riêng

Pattern nâng cao: Composite Alarm (AND/OR nhiều alarm con) tránh báo động giả. Case: sàn TMĐT bật Detailed Monitoring tạm thời dịp sale để scale sớm trước khi khách timeout.

Vị trí kiến trúc: Lớp phủ đồng hồ đo + còi báo động gắn lên mọi trạm, khác vai trò camera an ninh (GuardDuty/Config).

5 câu hỏi ôn tập
  1. Tránh báo động giả do spike ngắn, chỉnh gì? → evaluation-periods.
  2. Sàn TMĐT phát hiện quá tải nhạy hơn dịp sale? → Detailed Monitoring tạm thời.
  3. Kết hợp nhiều alarm AND/OR gọi là gì? → Composite Alarm.
  4. Metric mặc định lưu tối đa? → 15 tháng.
  5. Khớp đâu trong nhà máy? → Đồng hồ đo + còi báo động, khác camera an ninh.
aws cloudwatch put-metric-alarm --alarm-name high-cpu \
  --metric-name CPUUtilization --namespace AWS/EC2 \
  --statistic Average --period 300 --threshold 80 \
  --comparison-operator GreaterThanThreshold \
  --evaluation-periods 2 \
  --alarm-actions arn:aws:sns:...:topic/ops-alert

6.21 — Amazon CloudWatch Logs

Khái niệm: Thu thập, lưu, tìm kiếm log text. Log Group (nhóm theo app) + Log Stream (1 nguồn cụ thể). Như sổ nhật ký ca trực gom vào tủ hồ sơ theo phân xưởng.

Pattern nâng cao: Metric Filter biến pattern "ERROR" thành metric để alarm. Case: team K8s đếm "OutOfMemoryError" phát hiện memory leak sớm.

Vị trí kiến trúc: Nhánh mở rộng CloudWatch — sổ nhật ký chi tiết dạng chữ từ mọi trạm.

5 câu hỏi ôn tập
  1. Logs khác CloudTrail? → Log ứng dụng tự do vs log API có cấu trúc.
  2. Retention mặc định, rủi ro gì? → Giữ vĩnh viễn, tốn phí tăng dần.
  3. Biến "ERROR" thành metric gọi là gì? → Metric Filter.
  4. K8s phát hiện memory leak bằng gì? → Metric Filter + Alarm.
  5. Khớp đâu trong nhà máy? → Nhánh mở rộng CloudWatch, sổ nhật ký chữ.
aws logs create-log-group --log-group-name /myapp/prod
aws logs put-retention-policy --log-group-name /myapp/prod \
  --retention-in-days 30
aws logs create-log-metric-filter --log-group-name /myapp/prod \
  --filter-name error-count --filter-pattern "ERROR" \
  --metric-transformations metricName=ErrorCount,metricNamespace=MyApp,metricValue=1

6.22 — The Unified CloudWatch Agent

Khái niệm: Metric mặc định chỉ thấy "ngoài" instance (CPU/Network). Agent cài bên trong OS để thấy Memory/Disk %. Như nhân viên đứng trong xưởng báo cáo kho nguyên liệu bên trong sắp hết.

Pattern nâng cao: Đẩy log app + metric Memory cùng lúc qua 1 agent. Case: Java app OOM phát hiện được nhờ theo dõi Memory % — CPU vẫn thấp nên trước đó không phát hiện.

Vị trí kiến trúc: Nhánh mở rộng CloudWatch — cảm biến bên trong từng máy ở Xưởng lắp ráp.

5 câu hỏi ôn tập
  1. Vì sao mặc định không thấy % RAM? → Chỉ đo tầng hypervisor, không thấy trong OS.
  2. Muốn Memory Utilization cần gì? → Cài Unified CloudWatch Agent.
  3. Agent cần quyền IAM gì? → CloudWatchAgentServerPolicy.
  4. Case Java OOM phát hiện nhờ gì? → Theo dõi Memory % qua Agent.
  5. Khớp đâu trong nhà máy? → Cảm biến bên trong máy, nhánh CloudWatch.
sudo yum install amazon-cloudwatch-agent -y
sudo /opt/aws/amazon-cloudwatch-agent/bin/amazon-cloudwatch-agent-ctl \
  -a fetch-config -m ec2 -s \
  -c file:/opt/aws/amazon-cloudwatch-agent/etc/config.json
So sánhMetric mặc địnhAgent
Phạm viNgoài instanceTrong OS
Cần càiKhôngCó + IAM Role

6.23 — AWS CloudTrail

Khái niệm: Ghi mọi lệnh gọi API (ai, khi nào, gọi gì). Event History mặc định 90 ngày; Trail để lưu lâu dài/multi-region. Như camera an ninh + sổ ra vào ghi ai mở cửa nào.

  • Management events: bật mặc định
  • Data events: bật thêm, tốn phí cao hơn

Pattern nâng cao: Log file integrity validation cho forensic. Case: security dùng lookup-events lọc GetObject để xác định ai đọc file nhạy cảm.

Vị trí kiến trúc: Lớp phủ camera an ninh — sổ ghi ai làm hành động gì (khác Config = trạng thái).

5 câu hỏi ôn tập
  1. Event History mặc định lưu bao lâu? → 90 ngày, chỉ Management events.
  2. Ghi log API ở tất cả region dùng flag nào? → --is-multi-region-trail.
  3. Data events khác Management events? → Mức dữ liệu (S3 GetObject...), phải bật thêm.
  4. Chứng minh log chưa bị sửa? → Log file integrity validation.
  5. Khớp đâu trong nhà máy? → Camera an ninh, sổ ghi hành động.
aws cloudtrail create-trail --name org-trail \
  --s3-bucket-name my-cloudtrail-logs --is-multi-region-trail
aws cloudtrail start-logging --name org-trail
aws cloudtrail lookup-events \
  --lookup-attributes AttributeKey=Username,AttributeValue=alice
So sánhEvent HistoryTrail
Lưu90 ngàyVô thời hạn (S3)

6.25 — Amazon EventBridge (Refresher)

Khái niệm: "Bảng thông báo" route event theo rule tới target. Bài này kết hợp với CloudTrail để phản ứng tức thời theo hành vi API — khác Config Auto Remediation (theo chu kỳ trạng thái).

Pattern nâng cao: Rule bắt StopLogging/DeleteTrail. Case: fintech tự động bật lại logging + alert SNS trong vài giây khi phát hiện ai cố xóa dấu vết.

Vị trí kiến trúc: Vẫn là hệ thống loa phóng thanh (từ Module 5), nay nhận thêm tin từ CloudTrail.

5 câu hỏi ôn tập
  1. Khác Config Auto Remediation ở tốc độ? → Gần tức thời vs theo chu kỳ.
  2. Dấu hiệu kẻ tấn công xóa dấu vết? → StopLogging/DeleteTrail.
  3. 1 rule gắn tối đa bao nhiêu target? → 5.
  4. Fintech dùng để làm gì? → Tự bật lại logging + alert ngay.
  5. Khớp đâu? → Loa phóng thanh, nhận thêm tin từ CloudTrail.
aws events put-rule --name detect-trail-tamper \
  --event-pattern '{"source":["aws.cloudtrail"],
  "detail":{"eventName":["StopLogging","DeleteTrail"]}}'
aws events put-targets --rule detect-trail-tamper \
  --targets '[{"Id":"1","Arn":"arn:aws:sns:...:topic/security-alert"}]'

6.27 — Metric Analysis and Tracing

Khái niệm: X-Ray vẽ bản đồ đường đi 1 request qua nhiều service (trace/segment), đo latency từng chặng. Như GPS gắn vào lô hàng đi qua nhiều trạm — biết chính xác kẹt ở đâu.

Pattern nâng cao: Sampling Rule 100% cho endpoint quan trọng. Case: sàn TMĐT khoanh vùng payment service chậm do gọi API ngân hàng ngoài, nhờ X-Ray Service Graph.

Vị trí kiến trúc: Nhánh mở rộng CloudWatch — GPS theo từng request xuyên suốt nhiều trạm.

5 câu hỏi ôn tập
  1. X-Ray trả lời câu hỏi gì CloudWatch không trả lời được? → Chậm ở chặng nào cụ thể.
  2. Sampling rate mặc định? → 1 req/giây + 5% còn lại.
  3. Trace 100% cho 1 API quan trọng làm sao? → Sampling Rule tùy chỉnh.
  4. Case sàn TMĐT phát hiện gì? → Payment service chậm do API ngân hàng ngoài.
  5. Khớp đâu? → Nhánh CloudWatch, GPS theo request.
aws xray get-trace-summaries \
  --start-time 2026-08-01T00:00:00 \
  --end-time 2026-08-01T01:00:00
aws xray get-service-graph \
  --start-time 2026-08-01T00:00:00 \
  --end-time 2026-08-01T01:00:00

Quiz — Monitoring, Logging, and Auditing

1. Metric mặc định EC2 có thấy được % RAM đang dùng không?
Không — cần cài Unified CloudWatch Agent để thấy metric bên trong OS.
2. Muốn alarm không kêu vì 1 spike CPU ngắn hạn, chỉnh tham số nào?
Tăng --evaluation-periods (số khoảng liên tiếp phải vi phạm).
3. Muốn biến số lần xuất hiện "ERROR" trong log thành alarm, dùng gì?
CloudWatch Logs Metric Filter.
4. Event History CloudTrail mặc định lưu bao lâu?
90 ngày, chỉ Management events, miễn phí.
5. Dấu hiệu kẻ tấn công cố xóa dấu vết trên CloudTrail?
Gọi StopLogging hoặc DeleteTrail.
6. Công cụ nào cho biết chính xác service nào trong chuỗi microservices đang chậm?
AWS X-Ray (Service Graph + Trace).
7. EventBridge + CloudTrail phản ứng nhanh hơn hay chậm hơn Config Auto Remediation?
Nhanh hơn — gần tức thời theo hành động API, thay vì theo chu kỳ đánh giá rule.
8. Chi phí ẩn hay gặp nhất khi setup CloudWatch Logs là gì?
Quên đặt retention policy → log giữ vĩnh viễn, chi phí tăng dần âm thầm.

Lab tổng — Dựng hệ thống giám sát + audit toàn diện

🧭 Bối cảnh: Thiết lập giám sát cho app trên EC2: Memory metric, alarm lỗi log, audit mọi API call, tự động cảnh báo khi ai cố xóa dấu vết log.

Verify:

aws cloudwatch describe-alarms --alarm-names high-cpu app-error-spike
aws logs filter-log-events --log-group-name /myapp/prod --filter-pattern "ERROR"
aws cloudtrail get-trail-status --name org-trail
aws events list-rules --name-prefix detect-trail-tamper

Cleanup:

aws events remove-targets --rule detect-trail-tamper --ids 1
aws events delete-rule --name detect-trail-tamper
aws cloudtrail stop-logging --name org-trail
aws cloudtrail delete-trail --name org-trail
aws s3 rb s3://my-cloudtrail-logs-2026 --force
aws logs delete-log-group --log-group-name /myapp/prod
aws cloudwatch delete-alarms --alarm-names high-cpu app-error-spike
⚠️ Lưu ý dễ sai/dễ tốn phí:
  • Quên retention policy cho log group → chi phí tăng âm thầm.
  • Multi-region trail ghi log mọi region — cần lifecycle rule dọn S3.
  • Agent cần IAM Role CloudWatchAgentServerPolicy, thiếu quyền sẽ chạy nhưng không đẩy được metric.
  • Data events CloudTrail tính phí theo số lượng — không bật tràn lan.

Cheat Sheet — Monitoring, Logging, and Auditing

CloudWatch vs Logs

CloudWatch = số liệu + báo động. CloudWatch Logs = lưu/tìm log text. Đừng nhầm.

Bẫy Memory Metric

Metric mặc định KHÔNG có Memory/Disk % — phải cài Unified CloudWatch Agent.

CloudTrail

Ai gọi API gì. Event History 90 ngày miễn phí; Trail để lưu lâu/multi-region.

EventBridge vs Config Remediation

EventBridge+CloudTrail = phản ứng tức thời theo hành động. Config = phản ứng theo chu kỳ đánh giá trạng thái.

X-Ray

Biết CHÍNH XÁC request chậm ở chặng nào trong kiến trúc microservices/Lambda.

Chi phí ẩn

Quên retention policy log group, bật Data events tràn lan trên CloudTrail.

🎯 Pattern chuẩn thi

Câu hỏi "audit ai làm gì" → CloudTrail. "Phát hiện lỗi ứng dụng dù CPU bình thường" → CloudWatch Logs Metric Filter. "Xác định chặng chậm trong microservices" → X-Ray. "Cần Memory metric" → nhớ phải cài Agent, không có sẵn.

🏭 Trạm mới thêm vào nhà máy nền

  • CloudWatch (metric/alarm) — đồng hồ đo + còi báo động gắn mọi trạm
  • CloudWatch Logs — sổ nhật ký chi tiết dạng chữ
  • Unified CloudWatch Agent — cảm biến bên trong Xưởng lắp ráp (EC2)
  • CloudTrail — camera an ninh, sổ ghi ai làm hành động gì
  • EventBridge — không mới, thêm nguồn tin từ CloudTrail
  • AWS X-Ray — GPS theo từng request xuyên suốt các trạm
