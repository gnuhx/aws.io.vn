Human in the Loop — interrupt()

Dừng graph giữa chừng, chờ con người duyệt, rồi resume đúng chỗ · ~28 phút

01Khái niệm + Ví dụ đời sống

Human in the Loop (HITL) = kỹ thuật làm graph tạm dừng tại 1 node, gửi payload ra ngoài chờ người duyệt, rồi resume lại đúng chỗ đã dừng — không chạy lại từ đầu.

Ví dụ đời sống: Trợ lý soạn email nhạy cảm gửi khách hàng → không tự bấm gửi → để nháp chờ sếp duyệt → sếp gật đầu/sửa → mới gửi thật.

Vì sao không "thoát hẳn rồi gọi lại từ đầu"? Vì các bước trước đó (gọi LLM, RAG...) tốn tiền + không deterministic — đóng băng đúng state hiện tại rẻ hơn nhiều so với build lại.

03Các lệnh quan trọng + nâng cao

interrupt(value) — dừng node, gửi payload ra ngoài

from langgraph.types import interrupt

def node_cho_duyet(state):
    quyet_dinh = interrupt({"cau_hoi": "Duyet khong?", "data": state["draft"]})
    # code sau dong nay CHUA chay cho toi khi resume
    return {"ket_qua": quyet_dinh}

value: bất kỳ dữ liệu nào — hiển thị cho người duyệt xem. Return value chính là dữ liệu resume gửi vào.

Command(resume=...) — tiếp tục graph đang treo

from langgraph.types import Command
app.invoke(Command(resume="Dong y, cho phep gui"), config=config)

Phải cùng config (cùng thread_id) với lần invoke đầu tiên.

Kiểm tra trạng thái đang treo

state = app.get_state(config)
print(state.next)                  # node sap chay tiep
print(state.tasks[0].interrupts) # payload dang cho

Bảng: interrupt() trong node vs interrupt_before/after (compile-level)

Cách dùngKhi nào chọn
interrupt() trong nodeCần payload + resume value tùy biến — khuyến nghị đa số use case thật
interrupt_before=[...]Chỉ cần dừng TRƯỚC 1 node cố định, không cần custom payload
interrupt_after=[...]Dừng SAU khi node chạy xong, review kết quả node đó

Resume kèm hành động (approve/reject/edit)

app.invoke(
    Command(resume={"action": "edit", "new_content": "..."}),
    config=config
)

⚠️ Dễ sai / dễ brick

  • Quên checkpointer khi compile → interrupt() lỗi
  • Đổi thread_id giữa 2 lần invoke → không resume đúng graph
  • Không bao giờ gọi resume → graph treo mãi mãi, không lỗi không crash
  • InMemorySaver + restart process → mất checkpoint đang treo
  • Side-effect không idempotent trước interrupt() trong cùng node → có thể chạy lại khi resume

🍡 Tanjiro Kamado và chiêu thức chưa được phê duyệt

Tanjiro vừa luyện xong 1 chiêu Thủy Trụ mới toanh. Nhưng luật của Diệt Quỷ Đội rất nghiêm: không đệ tử nào được tự ý dùng chiêu chưa qua kiểm chứng trong nhiệm vụ thật. Cậu buộc phải dừng lại — soạn xong chiêu, gói gọn thành 1 "hồ sơ xin duyệt" gửi lên Oyakata-sama (Cầm Dan Tan Bát), rồi đứng yên chờ. Không ai được bỏ qua bước này, kể cả trụ cột mạnh nhất.

Có lần, đệ tử phụ Genya nóng vội thi triển chiêu mới ngay giữa trận mà chưa đợi duyệt — kết quả: chiêu chưa kiểm chứng phản tác dụng, cậu phải rút lui và luyện lại từ đầu. Bài học: bỏ qua bước chờ duyệt trước hành động không thể hoàn tác luôn là rủi ro.

Khi Oyakata-sama gật đầu, đúng hồ sơ huấn luyện của Tanjiro (không lẫn với đệ tử khác), cậu mới được phép thi triển chiêu thức thật trong nhiệm vụ.

💻Code thật (langgraph 1.2.9, đã chạy)

from typing import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.types import interrupt, Command
from langgraph.checkpoint.memory import InMemorySaver

class TrangThaiHuanLuyen(TypedDict):
    ky_thuat: str          # chieu the vo dang soan
    danh_gia_oyakata: str  # phan hoi cua master sau khi duyet
    trang_thai: str        # ket qua cuoi cung

def soan_chieu_the(state: TrangThaiHuanLuyen) -> dict:
    """Node 1: Tanjiro tu soan chieu the moi (agent tu generate output)."""
    print(">> Tanjiro dang soan chieu the moi...")
    return {"ky_thuat": "Thuy Truong Hoa - Chieu thu 11: Xoay Nuoc Vo Tan"}

def cho_oyakata_duyet(state: TrangThaiHuanLuyen) -> dict:
    """Node 2: DUNG lai, cho Oyakata-sama (con nguoi) duyet - chinh la interrupt()."""
    quyet_dinh = interrupt({
        "cau_hoi": "Oyakata-sama, co cho phep dung chieu the nay khong?",
        "ky_thuat_de_xuat": state["ky_thuat"],
    })
    return {"danh_gia_oyakata": quyet_dinh}

def thi_trien(state: TrangThaiHuanLuyen) -> dict:
    """Node 3: Chi chay SAU KHI duoc duyet."""
    print(">> Tanjiro thi trien chieu the sau khi duoc duyet!")
    return {"trang_thai": f"Da thi trien: {state['ky_thuat']} | Phan hoi: {state['danh_gia_oyakata']}"}

graph_builder = StateGraph(TrangThaiHuanLuyen)
graph_builder.add_node("soan_chieu_the", soan_chieu_the)
graph_builder.add_node("cho_oyakata_duyet", cho_oyakata_duyet)
graph_builder.add_node("thi_trien", thi_trien)
graph_builder.add_edge(START, "soan_chieu_the")
graph_builder.add_edge("soan_chieu_the", "cho_oyakata_duyet")
graph_builder.add_edge("cho_oyakata_duyet", "thi_trien")
graph_builder.add_edge("thi_trien", END)

checkpointer = InMemorySaver()
app = graph_builder.compile(checkpointer=checkpointer)
config = {"configurable": {"thread_id": "tanjiro-training-001"}}

result_1 = app.invoke({"ky_thuat": "", "danh_gia_oyakata": "", "trang_thai": ""}, config=config)
state_now = app.get_state(config)
result_2 = app.invoke(
    Command(resume="Duoc phep. Chieu the on dinh, cho phep dua vao thuc chien."),
    config=config,
)

🧠Tại sao code này chạy được?

LangGraph không quan tâm field trong TypedDict tên là ky_thuat hay subject, câu hỏi trong interrupt() là tiếng Việt hay tiếng Anh, thread_id là "tanjiro-training-001" hay "student_123". Framework chỉ vận hành đúng 3 nguyên lý bất biến:

  • Có checkpointer → state được ghi lại theo thread_id sau mỗi super-step
  • interrupt() trong node → thực thi dừng lại, ném Interrupt object kèm value, đánh dấu thread "đang chờ"
  • Command(resume=X) đúng thread_id → khôi phục đúng vị trí, làm interrupt() đang treo trả về X, chạy tiếp phần code còn lại

Chuyện "Tanjiro xin Oyakata-sama duyệt chiêu thức" chỉ là tên biến và câu chuyện khoác lên trên — cỗ máy bên dưới xử lý y hệt dù đó là duyệt võ công, duyệt email, hay duyệt đề thi Toán lớp 9. Không phải phép màu — chỉ là nắm đúng nguyên lý.
