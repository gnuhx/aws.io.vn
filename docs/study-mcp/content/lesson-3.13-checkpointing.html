💾 Checkpointing là gì?

Checkpointing là cơ chế LangGraph tự động lưu lại toàn bộ state sau mỗi super step (1 nhịp thực thi). Mỗi lần lưu tạo ra 1 checkpoint — giống save file trong game.

🎮 Ví dụ đời sống: Dark Souls

Chạm bonfire → tự lưu tiến trình (checkpoint). Chết → respawn tại bonfire gần nhất (resume). Nhiều file save cho nhiều nhân vật → mỗi save là 1 thread_id riêng.

💬 Ví dụ: Chat đa lượt

ChatGPT/Claude giữ ngữ cảnh khi đóng tab, mở lại — nhờ mỗi hội thoại có thread_id, mỗi tin nhắn là 1 checkpoint lưu vào DB.

A. Khởi tạo checkpointer

from langgraph.checkpoint.memory import MemorySaver

checkpointer = MemorySaver()  # in-memory, mất khi restart — dev/test
app = graph.compile(checkpointer=checkpointer)
from langgraph.checkpoint.sqlite import SqliteSaver
import sqlite3

conn = sqlite3.connect("checkpoints.db", check_same_thread=False)
checkpointer = SqliteSaver(conn)  # lưu ra file .db — sống sót qua restart
app = graph.compile(checkpointer=checkpointer)
Flag / OptionÝ nghĩa

B. Thread ID — cô lập session

config = {"configurable": {"thread_id": "user_42_session_7"}}
app.invoke(initial_state, config)
⚠️ Cảnh báo: Không có thread_id → không thể tra cứu / time travel đúng ý, mỗi invoke như một phiên hoàn toàn mới.

C. Time travel — xem lịch sử

history = list(app.get_state_history(config))
for snap in history:
    print(snap.values)   # state tại checkpoint đó
    print(snap.next)     # node kế tiếp nếu resume
    print(snap.config)   # chứa checkpoint_id để resume chính xác
FieldÝ nghĩa
snap.valuesstate dict tại thời điểm đó
snap.nexttuple tên node kế tiếp (rỗng nếu đã kết thúc)
snap.configthread_id + checkpoint_id — dùng để resume chính xác
snap.metadatastep số mấy, writes gì, source (input/loop/fork)
snap.parent_configconfig của checkpoint cha

D. Replay / Fork từ checkpoint cũ

target_snapshot = history[1]
# invoke(None, ...) = tiếp tục chạy, không thêm input mới
result = app.invoke(None, target_snapshot.config)
# Time travel có SỬA state trước khi chạy tiếp
new_config = app.update_state(
    target_snapshot.config,
    {"so_luot_luyen": 99},
)
result = app.invoke(None, new_config)
LệnhGiải thích
get_state(config)State hiện tại mới nhất của 1 thread
get_state_history(config)Toàn bộ lịch sử checkpoint của 1 thread

E. Checkpoint Internals (nâng cao)

CheckpointTuple(
    config,          # thread_id + checkpoint_id
    checkpoint,      # channel_values, channel_versions, versions_seen
    metadata,        # source: "input" | "loop" | "fork", step, writes
    parent_config,   # config checkpoint cha (None nếu gốc)
)

Super step: 1 nhịp thực thi — tất cả node chạy song song trong 1 nhịp chỉ tạo 1 checkpoint duy nhất, không phải 1/node.

🍡 Story Mode — Tanjiro và Vết Khắc Trên Kiếm Nichirin

Tanjiro nhận nhiệm vụ hạ gục một con quỷ trong rừng tre. Mỗi khi hoàn thành 1 giai đoạn — khởi hành, luyện thở, báo cáo lên Đoàn Diệt Quỷ — cây kiếm Nichirin của cậu tự động khắc lại một vết chuẩn vào lưỡi kiếm. Đây chính là Checkpointer: nó không quan tâm câu chuyện là gì, chỉ âm thầm lưu lại "mọi thứ đang ở đâu" sau mỗi bước.

🐛 Bug hài hước: Zenitsu (đồng đội) hoảng loạn ngất xỉu ngay trước khi báo cáo, làm gián đoạn flow giữa chừng. Nhưng vì kiếm đã khắc đủ vết chuẩn, Tanjiro không cần luyện thở lại từ đầu — cậu tra lại vết khắc gần nhất trước bước báo cáo và tiếp tục đúng từ đó.

Mỗi nhiệm vụ có một mã nhiệm vụ riêng (thread_id = "tanjiro_001") để không lẫn với nhiệm vụ song song của Inosuke hay Zenitsu.

Code (đã chạy kiểm chứng thật)

from typing import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import MemorySaver


class NhiemVuState(TypedDict):
    ten_nhiem_vu: str      # Tên nhiệm vụ diệt quỷ
    so_luot_luyen: int     # Số lần luyện thở trong lúc thực hiện nhiệm vụ
    log: list               # Nhật ký nhiệm vụ, giống các "vết khắc" trên kiếm


def khoi_dong(state: NhiemVuState) -> dict:
    # Bước 1: Tanjiro nhận nhiệm vụ -> vết khắc đầu tiên trên kiếm
    return {"log": state.get("log", []) + [f"Bắt đầu nhiệm vụ: {state['ten_nhiem_vu']}"]}


def luyen_tap(state: NhiemVuState) -> dict:
    # Bước 2: Luyện "Nhất Thể Hô Hấp" -> vết khắc thứ hai
    so_luot = state["so_luot_luyen"] + 1
    return {"so_luot_luyen": so_luot, "log": state["log"] + [f"Luyện tập lần {so_luot}"]}


def bao_cao(state: NhiemVuState) -> dict:
    # Bước 3: Zenitsu lẽ ra phải báo cáo, nhưng có thể "ngất xỉu" giữa chừng
    # trong kịch bản thật -> checkpoint trước đó sẽ cứu tiến trình (xem phần replay)
    return {"log": state["log"] + ["Báo cáo hoàn tất nhiệm vụ"]}


graph = StateGraph(NhiemVuState)
graph.add_node("khoi_dong", khoi_dong)
graph.add_node("luyen_tap", luyen_tap)
graph.add_node("bao_cao", bao_cao)
graph.add_edge(START, "khoi_dong")
graph.add_edge("khoi_dong", "luyen_tap")
graph.add_edge("luyen_tap", "bao_cao")
graph.add_edge("bao_cao", END)

# Checkpointer = "kiếm Nichirin" tự động khắc vết sau mỗi super step
checkpointer = MemorySaver()
app = graph.compile(checkpointer=checkpointer)

# thread_id = mã nhiệm vụ riêng của Tanjiro, không lẫn Zenitsu/Inosuke
config = {"configurable": {"thread_id": "tanjiro_001"}}

result = app.invoke(
    {"ten_nhiem_vu": "Ha guc Ma quy", "so_luot_luyen": 0, "log": []}, config
)
print("=== KET QUA CUOI ===")
print(result)

print("\n=== TIME TRAVEL: tra lai cac vet khac tren kiem ===")
history = list(app.get_state_history(config))
for i, snap in enumerate(history):
    print(f"[{i}] next={snap.next} values={snap.values}")

print("\n=== ZENITSU NGAT XIU: chon vet khac TRUOC luc bao cao ===")
target = next(s for s in history if s.next == ("bao_cao",))
print("Checkpoint duoc chon de replay:", target.values, "| next:", target.next)

replayed = app.invoke(None, target.config)
print("\n=== KET QUA SAU KHI TIEP TUC NHIEM VU TU VET KHAC CU ===")
print(replayed)

Tại sao code này chạy được: LangGraph không hề biết và không quan tâm state tên là ten_nhiem_vu hay câu chuyện là Tanjiro. Với LangGraph, state chỉ là 1 dict theo TypedDict, checkpointer chỉ làm đúng 1 việc cơ học: serialize dict đó + tên node kế tiếp, sau mỗi super step, gắn với 1 thread_id. Time travel hoạt động được vì (1) mỗi checkpoint lưu đủ thông tin để biết node nào chạy tiếp (snap.next), nên invoke(None, config) chỉ là "tiếp tục đúng vị trí trong graph đã compile"; (2) thread_id chỉ là 1 khóa tra cứu trong storage — đổi tên biến, đổi ngôn ngữ kể chuyện không ảnh hưởng gì. Đây là lý do bạn có thể đổi NhiemVuState thành ExamGenState (roadmap Exam Generator v3) mà toàn bộ logic checkpoint/time-travel giữ nguyên y hệt.
