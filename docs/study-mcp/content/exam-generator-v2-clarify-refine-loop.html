1. Vấn đề của v1 → tại sao cần v2

v1 chỉ có graph thẳng — không hỏi lại, không sửa được. v2 thêm 2 cơ chế lõi: conditional edge (rẽ nhánh theo state) và cycle (quay lại node trước đó), cộng thêm stop condition để loop không chạy vô hạn.

START→ parse_request→ condition?
↳ thiếu fieldask_clarify→ END (chờ user)
↳ đủ fieldgenerate_exam→ collect_feedback→condition?
↳ "khó quá" & chưa đủ maxbump_refine ⟲ quay lạigenerate_exam
↳ ok hoặc đã đủ max_refinefinalize→ END

2. Ví dụ đời sống

Tiệm may đo áo: "May cho tôi cái áo" → thợ hỏi lại vải/size/kiểu (conditional edge). Đủ info → cắt áo mẫu. Mặc thử chê chật → thợ quay lại đúng bước chỉnh áo với số đo mới (loop), không hỏi lại từ đầu. Nhưng tiệm chỉ sửa miễn phí tối đa 3 lần — lần thứ 3 dù còn chê vẫn giao áo (stop condition), tránh sửa vô hạn.

5. Code mẫu (đã chạy thật)

def route_after_feedback(state) -> str:
    if state["refine_count"] >= state["max_refine"]:
        return "finalize"   # stop condition check TRƯỚC
    if "khó" in state["feedback"]:
        return "refine"
    return "finalize"

graph.add_conditional_edges("collect_feedback", route_after_feedback,
    {"refine": "bump_refine", "finalize": "finalize"})
graph.add_edge("bump_refine", "generate_exam")  # cycle

class TrangThaiRenKiem(TypedDict):
    yeu_cau_tho: str
    loai_quang: Optional[str]     # ~ subject
    kieu_dao: Optional[str]       # ~ exam_type
    hoa_van: Optional[str]        # ~ topic
    thanh_dao_da_ren: Optional[str]
    phan_hoi_tanjiro: List[str]
    phan_hoi_hien_tai: Optional[str]
    so_lan_ren_lai: int
    so_lan_toi_da: int
    do_sac: str
    nhat_ky: List[str]

def dieu_kien_sau_khi_thu(state) -> str:
    if state["so_lan_ren_lai"] >= state["so_lan_toi_da"]:
        return "chot_dao"
    if "nặng" in state["phan_hoi_hien_tai"] or "chê" in state["phan_hoi_hien_tai"]:
        return "ren_lai"
    return "chot_dao"

graph.add_conditional_edges("tanjiro_thu_dao", dieu_kien_sau_khi_thu,
    {"ren_lai": "hotaru_noi_gian_ren_lai", "chot_dao": "chot_dao"})
graph.add_edge("hotaru_noi_gian_ren_lai", "ren_kiem")  # cycle

Tại sao code này chạy được

LangGraph không quan tâm field tên là subject hay loai_quang, node tên là generate_exam hay ren_kiem — nó chỉ thực thi đúng theo cấu trúc đồ thị: cạnh nào nối tới đâu, hàm điều kiện trả về gì. Vì dieu_kien_sau_khi_thu giữ nguyên logic gốc (check max_refine trước, check nội dung feedback sau), hành vi graph — số vòng lặp, thời điểm dừng — giống hệt bản gốc dù vỏ ngôn ngữ khác hoàn toàn. Đây là do nắm đúng nguyên lý logic điều kiện + cấu trúc cạnh, không phải phép màu của việc đặt tên theo truyện.
