Khái niệm

State trong LangGraph là bộ nhớ dùng chung chảy qua toàn graph. Mỗi node trả về 1 dict chứa field cần cập nhật. Câu hỏi cốt lõi: giá trị mới sẽ ghi đè hay hợp nhất với giá trị cũ?

Replace (mặc định) giá trị mới ghi đè hoàn toàn giá trị cũ — dùng cho field chỉ cần "mới nhất".

Reducer (custom) giá trị mới được merge với giá trị cũ theo 1 hàm bạn định nghĩa qua Annotated — dùng cho field cần tích lũy.

Ví dụ đời sống

🏥 Sổ trực ca bệnh viện không có quy tắc → mỗi ca trực xé trang cũ viết đè lên → mất lịch sử điều trị. Đây là hành vi replace.

📖 Sổ có quy tắc "chỉ được thêm dòng mới vào cuối, không xóa dòng cũ" → cả lịch sử được giữ nguyên. Đây là reducer dạng append (giống operator.add).

🧮 "Điểm KPI = cộng dồn từ mọi ca trực" → đây là custom reducer, logic merge riêng, phức tạp hơn append đơn thuần.

Code: 3 chế độ reducer

import operator
from typing import TypedDict, Annotated

# 1) Không reducer -> mặc định REPLACE
class StateNoReducer(TypedDict):
    log: list[str]

# 2) Reducer có sẵn -> TÍCH LŨY (append)
class StateWithReducer(TypedDict):
    log: Annotated[list[str], operator.add]

# 3) Custom reducer -> MERGE theo logic riêng
def merge_scores(old: dict, new: dict) -> dict:
    merged = dict(old)
    for k, v in new.items():
        merged[k] = merged.get(k, 0) + v
    return merged

class StateCustomReducer(TypedDict):
    scores: Annotated[dict, merge_scores]

Ứng dụng thực tế

🔬 Multi-agent research: N agent con ghi findings vào state — bắt buộc reducer để không mất dữ liệu.

💬 Chat apps: lịch sử hội thoại luôn tích lũy — nền tảng add_messages.

🗺️ Map-Reduce: fan-out N node song song, field đích bắt buộc có reducer, nếu không kết quả bị ghi đè ngẫu nhiên.

📊 Audit/LangSmith tracing: giữ vết mọi bước xử lý với trace_log tích lũy.

🎓 Grading Agent (Exam Generator): nhiều agent chấm nhiều môn, cộng dồn điểm bằng custom reducer.

Lab steps tóm tắt

⚠️ Lỗi thường gặp

  • Quên Annotated → mất data âm thầm
  • operator.add trên dict → TypeError
  • Custom reducer quên return → state = None
  • Mutate old trực tiếp → side-effect với checkpointer

🍡 Story Mode — Tanjiro Kamado & Sổ Tay Biên Niên Sử

Đoàn Diệt Quỷ dùng chung 1 cuốn sổ ghi nhận trận đánh — đây chính là State của LangGraph. Mỗi Trụ Cột tham chiến là 1 Node. Câu hỏi trung tâm: khi 4 Trụ Cột lần lượt báo cáo, sổ sẽ cộng dồn hay chỉ giữ báo cáo mới nhất?

bien_nien_su = field có reducer operator.add → mọi báo cáo được nối vào cuối sổ, không ai bị mất tiếng nói.
bao_cao_tuc_thoi = field không reducer (default replace) → giống bảng tin cổng doanh trại, chỉ hiện tin mới nhất.
START → tanjiro → nezuko → zenitsu → inosuke → END = chính là Edges nối Node tuần tự (3.2).

🐛 BUG HÀI HƯỚC 1 Zenitsu ngủ quên giữa trận, tưởng mình "trốn việc" — nhưng report của anh vẫn tự động được ghi vào biên niên sử vì field có reducer, không phụ thuộc "thái độ" của node.

🐛 BUG HÀI HƯỚC 2 Inosuke gào thét định "đè" báo cáo người khác — nhưng reducer operator.add không cho phép ghi đè, chỉ cho phép nối thêm.

Code (đã chạy kiểm chứng thật)

"""
STORY MODE: Tanjiro Kamado & "So Tay Bien Nien Su" cua Doan Diet Quy
Anh xa: Lesson 3.3 - Reducers & Accumulating State (LangGraph)
"""
import operator
from typing import TypedDict, Annotated
from langgraph.graph import StateGraph, START, END

# STATE = "So Tay Bien Nien Su" dung chung cho ca doan diet quy (shared state)
class SoTayDietQuy(TypedDict):
    # co Annotated + operator.add => REDUCER "ghi bien nien su": moi Tru Cot bao cao
    # se duoc CONG DON vao so, khong ai lam mat bao cao cua nguoi truoc
    bien_nien_su: Annotated[list[str], operator.add]
    # KHONG Annotated => default reducer la "ghi de" (replace)
    bao_cao_tuc_thoi: str


def tanjiro_trinh_sat(state: SoTayDietQuy):
    ghi_chu = "Tanjiro: phat hien mui quy o lang gan nui"
    return {"bien_nien_su": [ghi_chu], "bao_cao_tuc_thoi": ghi_chu}


def nezuko_ho_tro(state: SoTayDietQuy):
    ghi_chu = "Nezuko: da chan dung quy o cong lang"
    return {"bien_nien_su": [ghi_chu], "bao_cao_tuc_thoi": ghi_chu}


# BUG HAI HUOC 1: Zenitsu ngu quen giua tran nhung van vo tinh tuan thu dung
# quy tac ghi so vi field co Annotated
def zenitsu_ngu_gat(state: SoTayDietQuy):
    ghi_chu = "Zenitsu: xin loi moi nguoi, toi vua ngu quen mat 5 phut"
    return {"bien_nien_su": [ghi_chu], "bao_cao_tuc_thoi": ghi_chu}


# BUG HAI HUOC 2: Inosuke xong xao, tuong minh se "de len" bao cao nguoi khac
# nhung reducer khong cho phep dieu do voi field bien_nien_su
def inosuke_xoc_dao(state: SoTayDietQuy):
    ghi_chu = "Inosuke: TA LA VUA NUI, xong vao chem quy khong can ke hoach!!"
    return {"bien_nien_su": [ghi_chu], "bao_cao_tuc_thoi": ghi_chu}


graph = StateGraph(SoTayDietQuy)
graph.add_node("tanjiro", tanjiro_trinh_sat)
graph.add_node("nezuko", nezuko_ho_tro)
graph.add_node("zenitsu", zenitsu_ngu_gat)
graph.add_node("inosuke", inosuke_xoc_dao)

graph.add_edge(START, "tanjiro")
graph.add_edge("tanjiro", "nezuko")
graph.add_edge("nezuko", "zenitsu")
graph.add_edge("zenitsu", "inosuke")
graph.add_edge("inosuke", END)

doan_diet_quy = graph.compile()
ket_qua = doan_diet_quy.invoke({"bien_nien_su": [], "bao_cao_tuc_thoi": ""})

print("=== BIEN NIEN SU (co reducer operator.add -> CONG DON tat ca) ===")
for i, dong in enumerate(ket_qua["bien_nien_su"], 1):
    print(f"{i}. {dong}")

print("\n=== BAO CAO TUC THOI (khong reducer -> GHI DE, chi con cai cuoi) ===")
print(ket_qua["bao_cao_tuc_thoi"])

Tại sao code này chạy được

LangGraph không quan tâm field tên là bien_nien_su hay messages, và không quan tâm nội dung là báo cáo diệt quỷ hay dữ liệu tài chính. Framework chỉ nhìn vào type annotation trong TypedDict: có Annotated[Type, reducer_fn] thì luôn gọi reducer_fn(cũ, mới); không có thì luôn replace.

Đây không phải "phép màu của thanh gươm diệt quỷ" — đó thuần túy là cơ chế merge cố định (return dict → gọi reducer nếu có → cập nhật state → truyền cho node kế tiếp), chạy dựa trên schema đã khai báo trước khi compile, không phụ thuộc "ý định" của node function. Hiểu đúng nguyên lý này giúp debug chính xác khi state trong hệ multi-agent (4.6, 4.7) bị mất dữ liệu hoặc ghi đè nhầm.
